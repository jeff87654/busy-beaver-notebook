TOOL (everything at idle priority, 1 core)
  rk7.exe (rk7.cpp) includes dlscan2.cpp, so K-configurations are parsed exactly as dlscan2 parses them. Modes:
    trace     literal run from the blank tape; prints every K-config in a template
    probe     next K-config / HALT / timeout from a constructed K(ds;a;b) read from stdin
    haltones  runs a constructed config to its halt; prints steps and ones
    follow    raw tape at each end event (for runs that leave the template)
  rank7.py IN.tsv [...] -o OUT.tsv [--settled settled.txt]   (OUT.log holds per-machine detail). Steps:
    1. refit_rules: re-fit R1 and R2 (on b>=1) and R3 (borrows over k=1..4 zeros, any tail digit) from targeted probes.
       dlscan2's R3 tail/e3 are NOT trusted (FINDING 1). Rows whose refit fails are marked +RULES?.
    2. Literal trace from the blank tape (3e8 steps / 3000 K-configs): find the first K-config, and check every
       consecutive pair against the rules (lockstep). Literal exhaustions that rebuilt are listed separately and are
       not counted as misses.
    3. runcheck: continue at the rule level from the last literal K-config and probe each config literally (while
       values <= 3000). randcheck: 60 random configs, 60% of them forced to borrow over k=1..4 zeros.
    4. Model: F0(b) = m1 b + c1;  F1(b) = F0^(m2 b + c2)(b2);  F_j(b) = F_(j-1)^(m3 b + c3 + e3 (j-1))(K_j),
       with K_j = F_(j-2)^t .. F_1^t F0^a3(b3). Values are exact below 1e40, then tracked as (residue mod Q=20160,
       level), with orbit/cycle tables per level. This gives the exhaustion accumulator b_E: its level (the estimate)
       and its residue.
    5. Exhaustion probes in two windows: b = 0..47 and b = 4n+40..4n+63. Thresholds such as "halts iff b < 2n" only
       show at large b. The real b_E then decides H / rebuild / leaves-template.
    6. P-inclusive re-analysis: if dlscan2's prefix P consists of digits (P=110 is the digit 2), rerun with P absorbed
       (P='-'). This exposes hidden top levels and the TRUE exhaustion (the X33/Y19/Z16 family).
    7. Round-2 sweep (modulus Q2=720): evaluate the exhaustion reached from each rebuilt list in the large window. The
       class transitions b mod per -> b_E2 mod per give either "never halts (rebuild forever)" or "HALT REACHABLE".
       This reproduced the dl3_hits invariants for the r/s/h/u/i/a/b/c/t machines and for X33/Y19/Z16. It is NOT trusted
       when the refit failed: A1/A2/B1 were called never-halting that way, and they halt. Such rows are now marked
       UNRELIABLE.
    8. Invariant search (find_invariants / invariant_check): looks for a linear form Phi = ca a + cb b + cd sum(ds)
       mod m (m = 2, 3, 4, 6) that every refit rule preserves (tested on 400 random rule steps). Then: Phi at the real run,
       which exhaustions b are compatible with it, whether any of those halts, and whether the rebuilds keep Phi. If every
       compatible exhaustion rebuilds and Phi is kept, the verdict is NEVER-HALTS(invariant). Skipped when the refit fails.
  Controls (check_controls.py; run it after every change to rank7.py): positive = BB(7) champion (level 13, halts) and
    champ_231 (level 21, halts); negative = X33 and dl3's sibling i (never halt). Status: ALL CONTROLS OK. For X33 and i

FINDINGS
 1. dlscan2's R3 fit only collects borrows over k=1 zero, because it stops at the first tail digit 2. So "tail=1, e3=0"
    in its params is often an unfitted DEFAULT. The real rules of the i/j/X33/Z16/Y19/r/s/h/u family have refill
    ... - 2k and a tail of 2s. With the wrong tail the parity of every level flips. That produced my two false alarms:
      X33 = 1RB1RA_0RC0RA_0LD1RC_1LE1LF_1LB1LE_0LA1LG_---0LE: claimed halt ~2↑^34; refuted by x33-check (Phi invariant).
      Z16 = 1RB1RA_0RC0RA_0LD1RC_1LE1LF_1LB1LE_1LA1LG_---0LE: claimed halt ~2↑^16; refuted by me. Its real R3 is
        3b+3-2k with tail 2; Phi = a + b + sum(ds) mod 2 is invariant, so every true exhaustion is odd and rebuilds.
    My lockstep (3000 literal K-configs) and random checks missed the flaw, because k>=2 borrows are rare early in real
    runs and in random configs. Both checks now force such borrows. Both machines are in OPEN_CANDIDATES.txt under
    SETTLED, with the refutation.
 2. Hidden top digits: for prefixes like P=110 or P=10, dlscan2's "R4" config K(;0;b) is really a borrow from P's digit.
    The true exhaustion lies one or two levels further up. The P-inclusive re-analysis now handles this automatically.
 3. Y19 = 1RB1RA_0RC0RA_0LD1RC_0LE1LE_---1LF_1LA0LG_1LB1LG (level 19-20 if it halted): NEVER HALTS. Its true exhaustion
    halts iff b is even. With the correct R3 every F_j flips parity, and the real run never reaches an even class. The
    round-2 sweep agrees.
 4. P=101 family M1/M2/M3 (1RB---_1LC0LG_1RF1RD_0RF0LE_0LC1LB_1RA0RC_{1LB,1RB}0LE and 1RB0LE_1LC0LA_..._1RB---):
    NEVER HALT. P's "0 digit" is half a separator. An exhaustion-size lemma (b_end >= v+L+1) keeps every borrow and
    every exhaustion on the rebuild branch. Rules checked on 3000+ random literal configs (k up to 45). Details in
    p101/notes.txt (subagent).
 5. C1 = 1RB0RD_0RC1RG_1RD1RC_1LD0LE_0RB1LF_0LC1LE_---1RA: NEVER HALTS (in v-coding, r is never 1 mod 3 at an
    exhaustion). Details in f3/notes.txt.
 6. A1/A2/B1 halt, at small values (see BOTTOM LINE). Their R3 refits failed because of an ABSORB rule:
    [..,z,0,0;a] == [..;a+z+2].

LIMITATIONS
  Rules are fitted from literal probes and checked on literal runs and random configs; nothing is proved. The level
  estimate is a crude up-arrow interpolation (+-1). The residue evaluation assumes that cycle lengths divide Q (it flags
  them when they don't; this never happened here). Rows marked +RULES? are not modelled faithfully.
