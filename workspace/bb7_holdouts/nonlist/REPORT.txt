with peak ratio >= 1.4) keeps ~65% of the pool (doublers are everywhere: peaks 16,32,64,...), so it was rejected.

3. PROBE DESIGN (nlp7.cpp; binaries nlp7.exe = stage P, nlp7f.exe = stage F, nlp7v.exe = post/hand tools)
---------------------------------------------------------------------------------------------------------
Macro simulator: K-cell blocks, run-length stacks, self-loop acceleration over runs of identical blocks (exact: BB(5)
47,176,870 steps / 4098 ones at every K; a pool halter at 1,162,114,440 steps cross-checked by plain simulation).
Snapshots at tape-end events, one series per (end, state); run patterns compressed coding-agnostically (any block, any
period up to 4 runs).  Per machine (stage F, 1M macro at the pilot K + 0.5M at K=2):
  FAST   natural base steps >= 1e9.8;
  D      list length = count of the longest-LIVED repeated run pattern (pattern+count unchanged >= 50% of the run;
         this rejects period-3/4 accumulators seen in misaligned blocks and translated trails);
  FR     refilled frontier digit: a run within 8 runs of the list that decrements by 1 after >= 3 unchanged
         snapshots, >= 2 times, value >= 6 and < half the largest run (the borrow/refill signature of f_omega);
  small  forced small instance: list cut to 2-3 items, every counter (>= 3 falls, >= 24) cut to its residue mod 6
         (min 2), 2M macro at K = 2, the list K and the pilot K -> HALT reachable (heuristic, residues distorted);
  HT     same without the list cut: rounds spent per list item while the forced run consumes the list; growing
         intervals = hierarchical list.
Ranking by estimated size (never by grade): tier 1 = FR > 0 and D >= 4, ordered by HT, D, FR; tier 2 = FR > 0 and
small HALT; tier 3 = other FR; tier 4/5 = no FR (unary lists, counters).  Then hand examination of tier 1 and of all
FR families with >= 24 runs (lists of DIFFERENT digit values do not show in D).
The hand step decides the key question the probe cannot: are list items CONSUMED (unary list: one exponentiation per
item, a tower, ~3 arrows: lead L1) or REFILLED in place by accumulator-sized values (digit list: 1-2 arrows per item,
champ_231 / H1)?  Method: --dumpat a natural tape, edit counts (msrun.py), run constructed exhaustions and borrows.

4b. L1 (lead request): 1RB---_1RC1RD_0LD1LC_1RF0LE_0LG1LC_0RB0RG_0RA1LD
--------------------------------------------------------------------------
Rules (K=6, constructed tapes from a natural dump, exact macro simulation; l1/ and notes.txt):
  level 1: transfer pair (010)^a/(100)^b, ACC x9 per cycle (the lead's independent (u,v,w)->(9u+52,v-3,w-1));
  digits: d2 is reloaded with a CONSTANT (~3459, independent of ACC); d1 is refilled with ~36*ACC; d1 x d2 count the
          cycles, so one list item = one exponentiation of ACC;
  list item consumed when d1,d2 exhaust; LIST EXHAUSTED -> REBUILD: a new list of ~8a+19 pairs is written from the
          accumulator a (a = 3, 9, 27, 60 -> 43, 91, 235, 499 pairs), d2 := 3458, d1 := ACC-sized; the far-end marker
          goes 001010 010000 -> 100101 001000 -> 110010 100100 and then stays fixed: there is NO round counter.
Branch at list exhaustion: REBUILD for every tested accumulator pair, (b,a) in 1..24 x 1..24 in the first two
  phases and 1..12 x 1..12 in the stable phase (5M macro steps each); no halt anywhere.  The real first list
  exhaustion (after ~3^^6936) has an accumulator whose residues were not computed: halting is UNDECIDED, all evidence
  says rebuild.
Size class: round map a_{r+1} ~ 9^^(c a_r) (c ~ 2..8; pentation per round, 3 arrows), rounds unbounded and uncounted.
  If L1 never halts it is not a candidate; if it halts after round R, sigma ~ 9^^^R.  Beating champ_231 (20 arrows)
  would need R >= ~3^^^...^3 (19 arrows) rounds, i.e. a halt gated on a residue condition that first opens at an
  astronomically late round; nothing in the rules counts rounds.  Verdict: NOT RECORD CLASS (3 arrows per round),
  halting UNDECIDED (probable never-halts by rebuild).

5. WHY THE VERDICT IS NEGATIVE, AND THE GAPS
--------------------------------------------
- A record needs ~20 hierarchical levels; the probe's FR signature was present for every f_omega control, and every
  FR family was either examined by hand (tier 1 all; tiers 2/3 with >= 24 runs) or has D < 4 and < 24 runs (no room for
  a 20-level list).  The only hierarchical lists found rebuild instead of halting (H1 class: logged OPEN).
- Gaps: (a) FAST machines with a slow start (2 of 330 in the sample, ~0.6%) (P2 < 8.0) and machines whose hierarchy needs more than 1M macro
  steps to show; (b) tier 4/5 (no FR, 11,147 families) were not examined by hand: all unary lists seen so far had no
  FR, and every f_omega control had FR; (c) rebuild-then-halt machines (dl3-looper type) are not detected by the small
  probe; (d) the halting analyses of the H1 class are scans, not proofs; (e) the small probe is residue-distorting.
- 397 natural halters were not checked against bbchallenge's list semantics; they halt with <= 420,675 ones.
