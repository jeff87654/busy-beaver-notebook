# BB inverse compilation

This directory is the first implementation of
`BB Inverse Compilation — Project Spec.md`: specify an abstract Hardy-style
counter, synthesize a small two-symbol Turing machine that implements one
abstract step between checkpoints, and test the candidate on instances that
were not used to guide the first search round.

## Current status

Milestone M0 is implemented, together with a first Engine-A calibration
pilot and a symbolic verifier for one abstract step.  Both discovered
one-digit candidates are now proved for every `n` and `d` under their stated
encodings.  The M2 expressivity check against the BB(6) and BB(7)
champions is also done (see below): BB(7)'s abstract rule system fits an
extended sloppy-Hardy template family, while BB(6)'s does not fit the
affine template/verifier language at all.  This is still not a Busy Beaver
result: the synthesized tables are rule fragments for externally prepared
encoded tapes, and they have no blank-tape initialization, iteration, or
growth theorem yet.

The headline pilot result is that the checkpoint head anchor matters more
than the first block encoding choice:

- With the head at the right end of the `n` block, Engine A finds the
  one-digit transfer rule `d -> d-1, n -> n+1` at three states with offset 0
  and at four states with offset 1.
- The first two-digit refill rule, which must copy `n` into `d0`, is the
  scaling cliff.  Free search at four, five, and six states and a sketched
  search at seven states all exhausted their node budgets without a
  candidate.  A champion-inspired consuming/doubling variant (below) does
  not fall to Engine A at five to seven states either.

## Symbolic results

The machine-readable record is `results/symbolic_pilot.json`, generated by
`symbolic_pilot.py`.  The verifier uses affine run lengths and executes
same-state sweeps as shift rules, with `proved`, `counterexample`, and
`unknown` kept distinct.

- Both discovered one-digit candidates: `proved` for all `n,d`.
- A hand-built left-anchor sweep machine: `proved`, including a generic
  `2*n+4`-step successor branch.
- An always-halting negative control: `counterexample`.
- The two-digit successor sketch: its `d0 > 0` case is `proved` for all
  `n,d0,d1`; refill and all-zero halting are `unknown` exactly at the
  deliberately unassigned C0 transition.

As an independent concrete cross-check, the maintained tests also run both
discovered tables over the finite box `n,d <= 8`.

`certify.py` composes a proved one-step simulation over a whole abstract
run: for the offset-zero candidate started at `(0, (60,))` it certifies a
halting run of exactly 184 machine steps (lower bound 61 from the
abstract trace alone), cross-checked leg by leg against the abstract
successors.  `growth.py` records the exact digit-clearing closed form
for the consuming/doubling variant (`A -> 2^v A + 2(2^v - 1)`) and
finite-grid domination evidence against the textbook counter; the
general phase-induction domination proof is sketched there but not yet
formalized.

## Champion expressivity (M2)

The machine-readable record is `results/champions_pilot.json`, generated
by `champions_pilot.py`.  Both champions were traced from the blank tape
with the literal simulator.

**BB(7)** (`1RB0RA_1LC1LF_1RD0LB_1RA1LE_1RZ0LC_1RG1LD_0RG0RF`).  The
blank run reaches B-form checkpoints from step 2,154 onward, including
the analysed start `B(2; [1]*12)` at step 8,178, and every traced
transition between consecutive B-forms follows the derived rules.  In the
empirical parameterization forced by the traced tapes (digit value `d`
as a `1(01)^(3d+1)` token, accumulator `A` as a `(01)^(3A)` token), the
rules are: successor `d0 -= 1, A := 2A + 2`; refill
`d_{k-1} := 2A + 2, d_k -= 1, A := 0`; halt at all-zero digits.  That is
a sloppy Hardy counter once the template language is extended with an
affine successor map and a consuming refill (both now in `abstract.py`),
but its tape encoding — `(01)` tokens, right-edge checkpoint, reversed
digit order — is outside the current unary-block encoding family.
Verdicts:

| BB(7) rule | Concrete | Symbolic |
|---|---|---|
| Low-level L1 (`01 1 (01)^n ... -> 1 (01)^(n+2) ...`) | passes `n <= 6` | **proved** for all `n` |
| Low-level L2/L3 as isolated tapes | halt (need left context) | not attempted standalone |
| Pair-transfer lemma (`(u, v) -> (u-1, v+2)`) | seen in trace sub-events | **proved** for all `u, v >= 1` |
| B successor | 60/60 constructed cases pass (all rule kinds) | **unknown** for generic `A`; branches `A = 0, 1` proved |
| Successor finish phase | included above | **unknown**; small-`v` branches proved individually |
| B refill (one leading zero) | included above | **unknown** for generic `A`; branch `A = 0` proved |
| B halt (all-zero digits) | included above | **unknown** (step bound) |

The B successor decomposes as `3A` iterations of the proved pair-transfer
lemma followed by the finish phase, so the remaining symbolic blocker is
precisely that finish phase (and its refill analogue): it converts a
`(01)^v` token pair by pair, and the verifier's new counter-induction
acceleration does not trigger there because the item list keeps growing
(new cells are written at the right edge), so no exact item-shape cycle
repeats.  A re-segmentation-invariant cycle detector is the missing
piece.  No champion rule was refuted; every concrete check passes.  The
champion also passes all 20 of its own abstract instances over the new
`(01)`-token encoding (`token_encoding.py`, with a B-form checkpoint
predicate), while Engine A finds no 7-state machine in that encoding
within 60,000 nodes on the smallest seven instances.

**BB(6)** (`1RB1RA_1RC1RZ_1LD0RF_1RA0LE_0LD1RC_1RA0RE`).  The blank run
reaches a degenerate S1 form at step 140 and the analysed start
`S1(3, 7, 2, 6, 63)` at step 27,965, with no other S1 form in between.
All 28 constructed Inc0/Inc1/Inc2/Rst0/Rst1 checks pass.  But those rules
contain `2^b` run lengths and a binary (LC) digit encoding: they are not
expressible in the affine template language, and neither symbolic
verifier can even state them.  Verdict: **unknown / not expressible** —
BB(6) is a genuinely different architecture from the Hardy-counter
family this pipeline searches, exactly the blind spot the spec accepts
for non-counter champions.

Engine B (`sat_engine.py`, SAT bounded model checking) is implemented
and validated on the one-digit transfer (it finds a 3-state machine in
under a second).  On the one-digit doubling successor it has not yet
produced a candidate within the attempted bounds.

## Layout

- `abstract.py` — Hardy-style counters over digit lists and template
  parameters.
- `encoding.py` — unary block encodings with `left` and `n_right`
  checkpoint head anchors.
- `tm.py` — standard-format parsing/formatting and a literal simulator that
  runs from arbitrary configurations to a checkpoint.
- `instances.py` — conversion of abstract steps into concrete checkpoint
  tests, either over a finite box or over reachable configurations only.
- `engine.py` — Engine A, a depth-first spec-pruned synthesizer, plus a
  small train/holdout CEGIS loop.
- `sat_engine.py` — Engine B, SAT bounded-model-checking synthesis over
  the same concrete instances (PySAT).
- `champions.py` — BB(6)/BB(7) champion tables, checkpoint parsers,
  blank-tape tracing, and concrete rule checks.
- `sketches.py` — pinned transition fragments.  The current successor
  sketch leaves exactly the `d0 = 0` refill entry unassigned.
- `verify.py` — bounded counterexample search with `pass_bounded`,
  `counterexample`, and `unknown` outcomes.
- `symbolic.py` — affine run-length verification of one abstract step for
  all values at a fixed digit-list length.
- `pattern_symbolic.py` — verification over repeated tape words such as
  `(01)^n`, for champion-style right-edge checkpoint rules, with
  counter-induction loop acceleration.
- `token_encoding.py` — BB(7)-style `(01)`-token encoding and the B-form
  checkpoint predicate for synthesis instances.
- `certify.py` and `growth.py` — whole-run composition of proved steps,
  and growth/domination facts for the consuming/doubling variant.
- `pilot.py`, `symbolic_pilot.py`, and `champions_pilot.py` — reproducible
  synthesis, symbolic, and champion records described above.
- `tests/test_inverse_compile.py` — maintained unit and behavioral tests.

## Running it

Run all commands from the workspace root (the directory containing
`inverse_compile/`):

```powershell
python -m unittest inverse_compile.tests.test_inverse_compile -v
python -m inverse_compile.pilot --profile full
python -m inverse_compile.symbolic_pilot
python -m inverse_compile.champions_pilot
```

For a fast smoke run of only the solved one-digit searches:

```powershell
python -m inverse_compile.pilot --profile quick --skip-counter2
```

## Next gates

1. Make cycle detection re-segmentation-invariant (canonical greedy-block
   form for symbolic tapes) so counter-induction acceleration triggers on
   the BB(7) finish phase and the B successor/refill rules prove for
   generic accumulator values; the pair-transfer lemma already proves.
2. Scale Engine B on the doubling successor, the consuming two-digit
   counter, and the token encoding: smaller instance sets, incremental
   solving, solver time budgets, and sketches.
3. Formalize the consuming/doubling domination induction and extend
   whole-run certification from exact finite starts to ordinal growth
   bounds (abstract termination plus per-leg step formulas).
4. Add blank-tape initialization as its own synthesis instance into a
   distinct phase state.
5. Record a replayable shift-rule proof trace and export it to Rocq.  The
   present branch record is diagnostic evidence from a trusted Python
   verifier, not an independently checkable proof certificate.
