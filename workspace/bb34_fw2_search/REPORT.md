## 0. 结论（先说答案）

1. **用户提出的"折叠改写"是正确的、而且可以用 6 状态 4 符号精确实现**。已验证规则：

   ```
   停机配置   3^(2m+1) 2^k A> 2      --折叠-->    3 2^(2m+1) A> 1^k 2
   即         B(k, 0, m)             --折叠-->    B(2m+1, k, 0)
   ```

   即：**核心累积出的 m 变成新的"层级" k，原来的层级变成新的 n**。这是真正的层级提升（不是模拟拟合），
   并且链条**可以重复**：种子 (m,k)=(0,1) 的折叠触发序列为 (m,k) = (0,1) → (1,1) → (6,3)，
   层级 2m+1 = 1 → 3 → 13 → …

2. **但这台机器永不停机**（`A2` 把每次停机重定向进折叠）。它是一台"f_ω 迭代引擎"，不是记录。
   空白带启动后层级为  
   L₁ = 2↑^15(5) − 3， L_(j+1) ≈ 2↑^(L_j)(5)，  
   即 j 次折叠 ≈ f_ω^j。而 f_(ω+1)(n) = f_ω^n(n) 需要**折叠次数由外层计数器控制**。

3. **在 4–6 状态内无法给这个折叠加外层计数器。** 所有三种放置位置都被实测否决（见 §3）：
   计数器放块内会被折叠的**均匀横扫**规范化掉；放块左侧紧邻会被**核心的左向增长吸收**（实测全部变成 3）；
   放 0 间隔之外会被核心增长**写穿**（实测最左指针跑到标记左侧 150+ 格）。
   这与项目 `STATUS.md`/`METHODS.md` 的"磁带覆写障碍"完全一致。

4. **所以：4–6 状态 4 符号、走这条折叠路线，达不到 f_(ω+1)。** 能拿到的最好结果是
   ①5 状态：折叠一次就退化成无意义的自循环；②6 状态：折叠次数无界 ⇒ 永不停机；
   ③任意"停在第 j 次折叠"的变体：j 是常数 ⇒ f_ω^j（仍 < f_(ω+1)）。
   要真正达到 f_(ω+1)，最小结构是"折叠 gadget + 每折递减 1 的外层计数器 + 引导 3 的写回"（≥7 状态），
   而且计数器必须**由机器自己在空白带上生成**——Kropitz 的 241 步引导只产生 `3^33 2^16`，不产生计数器，
   这一步是真正的开放问题（2 符号的 n1 用了 10 状态才做到 f_(ω+1)，6 状态 4 符号不现实）。

## 1. 折叠的精确实现（6 状态，4 符号）

```
1RB3LB2LX2RA_2LC3RB1LC2RA_3RB1LB3LC2RC_3RY0LX1LX2LX_0RY1LW2RY0RY_0LA0LA2RA0LA
 A          B          C          X          Y          W
```

- **A2 = 2LX**：读 2（停机点），**写回 2**，左移进入 X。  
  ⚠ 关键细节：必须是 `2LX`，不能是 `1LX`。停机那个 `2` 正是核心唯一的停机判据（`B(k,0,m) 2`），
  折叠把它吃掉后核心就再也认不出自己的停机配置，链条会断。实测 `A2 = 1LX` 版本折叠后 2000 万步内
  只触发 1 次折叠（机器逃逸到右侧增长相位），而 `A2 = 2LX` 版本正常成链。
- **X**：`X2 = 1LX`（2→1，左行）、`X3 = 2LX`（3→2，左行）、`X0 = 3RY`（在最左的 0 上写新 3 并右转）。
  这正是用户描述的 "3 变 2、2 变 1、左边的 0 变 3"。
- **Y / W**：`Y2 = 2RY` 右行越过新 2 串，`Y1 = 1LW` 退到最后一个 2，`W2 = 2RA` 前进到
  **第一个 1** 上、状态回到 A。  
  ⚠ 第三个 gadget 状态 W 是**必需的**：只用 X、Y 两状态（5 状态机）时，指针只能停在"最后一个 2"
  或"第二个 1"，与 `B(k,n,m) = 0^∞ 3^(2m+1) 2^k A> 1^n` 的约定（指针在**第一个 1**）差一格。
  5 状态版本实测：回程落到最后一个 2 上，`A2` 立刻再次触发折叠，机器只会把 2 串一条条改写成 1，
  永远做不了核心工作（退化）。

## 2. 已验证的三件事

| 检查 | 结果 |
|---|---|
| 折叠输出块长 | `(3-run, 2-run, 1-run)` = `(1, 2m+1, k)`，右侧保留停机 2。对 (m,k) = (0,1),(0,4),(1,1),(2,3),(3,2) 全部吻合 |
| 与 Kropitz 核心等价 | 折叠后从 `B(2m+1,k,0)` 出发，与原核心（`A2 = 1RZ`）**轨迹逐步完全一致**：m≥1 时 200 000 步无差异；m=0 时一致到原核心的第 10/52 步停机点为止 |
| 链条可重复 | (m,k)=(0,1)：折叠触发于第 1、17、285 步，配置依次为 (m,k)=(0,1) → (1,1) → (6,3)，层级 1 → 3 → 13 |

空白带（`B(16,3,0)`，241 步引导）代入：

| 折叠次 j | 层级 L_j | 该段的步数量级 |
|---|---|---|
| 0（Kropitz 原机） | k = 16 | ≈ 2↑^15(5) |
| 1 | L₁ = 2↑^15(5) − 3 | 2↑^(L₁)(5) |
| 2 | L₂ ≈ 2↑^(L₁)(5) | 2↑^(L₂)(5) |
| j | L_(j+1) ≈ 2↑^(L_j)(5) | ≈ f_ω 每折一步 |

## 3. 为什么加不了外层计数器（三种放置都被实测否决）

外层计数器（长度 d 的 1 串）必须满足：熬过核心的左向增长、且被折叠每折恰好吃掉 1 格。三种位置：

1. **块内 / 紧邻 3 串左侧** —— 折叠的 X 横扫是**均匀**的（只区分 "2"、"3"、"其他"），
   任何嵌在块里的结构都被一并规范化，无法保留计数信息。
2. **紧邻 3 串左侧、不在块内** —— 实测被核心的**左向增长吸收**：在 `B(k,n,m) 2` 左侧放 `1^d`
   （d=3、B(1,2,1)，59 步停机），停机时该处读数为 `[3,3,3]`；d=2、B(2,2,1) 得 `[3,3]`；d=1 得 `[3]`。
   换成更大的配置（m=1,k=3,n=2）标记单元虽暂时保持 1，但机器随即偏离 Kropitz 规则、长时间不停机——
   即"墙效应"把内层计算破坏了。两种情况都不能当计数器用。
3. **隔一段 0 放在更左** —— 核心增长会**写穿** 0 间隔：`3^(2m+1) 2^k A> 1^n` 加 `1^d`+0^g 后，
   实测最左指针到达标记左侧 150 格以上（`minpos` 远小于标记位置），标记被绕/被改写。
   而且折叠前的 m 在天文数字级增长，任何固定距离的"墙"都会被第一折就摸到。

**根本原因（结构性的）：** Kropitz 核心把整个左侧都当作"结果累加区"（m 就是 3 串的半长），
而折叠的改写范围 = 整个 3 串 + 2 串，其长度无界。计数器和数据共用同一段一维磁带，二者不可能分离。
这正是项目里"每轮两端都被覆写 ⇒ 外层计数器无法存活 ⇒ 出口由余数决定，上限 f_ω^k"的那条障碍。

## 4. 若要 f_(ω+1)：缺的是什么

"每折恰好递减 1"的 gadget 是有的：把 `X1` 从 `0LX`（一口吃完整串 1，实测确实如此）改成 `0RY`
（在第一个 1 处停下、右转），就得到"一折一格"的计数器；再补一个状态把新的引导 3 写回最左的 2 上，
即 7 状态：

| 需求 | 状态数 |
|---|---|
| 核心 A,B,C | 3 |
| 折叠 X,Y,W | 3 |
| 每折递减 1 时写回引导 3 的额外状态 | 1 |
| **合计（并且计数器仍须由机器自己生成）** | **≥7** |

**开放点是引导（bootstrap）**：空白带需要在 241 步的 Kropitz 引导里额外生成"左端 1^d 计数器"，
而引导只写出 `3^33 2^16`；d 还必须能随内层计算增长才有意义（n1 的做法就是让内层列表长度**充当**
外层计数器）。这一步在 4–6 状态内没有状态预算。

## 5. 搜索方法上的提醒（为什么"搜"不能靠模拟）

- 任何包含这套核心的机器，空白带停机时间都不小于 Kropitz 的 ≈2↑^15(5) 步。
  因此**枚举 + 模拟**既发现不了也判不了这类机器（本项目 `BB13/search/search13.cpp` 之所以用
  符号化的"返回配置"判据 C_REL / D_REL / HALT，而不是跑完看停机，就是这个原因）。
- 本次"搜索"的方式是：固定 3 状态核心，按折叠模板把 3 个 gadget 槽位（4 符号 × 3 状态 = 12 条转移）
  逐一确定/穷举，用**返回配置判据**（折叠后必须精确等于带停机 2 的 `B(2m+1,k,0)`）来验收。
  在该模板族里，所有能停机的成员都是"固定折叠次数"，因此全部落在 f_ω^k。
- 6 状态 4 符号的完整空间约 10^30 量级，不可能穷举；真正有希望的方向不是"更多状态"，
  而是**把折叠从停机重定向改成中途重定向**（把核心内循环中的某条转移改道进折叠 gadget），
  让折叠次数天然由 n（内层迭代次数）控制而不是由外层计数器控制。这一点本次没有展开验证，
  是下一个值得做的实验。
