# Formal verification of Wade's 393-state ZF machine — design

Goal (Coq 8.20 + busycoq TM semantics):

    Theorem main : halts tm c0 <-> prov (wel v0 v0).

where `tm` is the 393-state 2-symbol machine `ext/turing_machine_explorer/zf2.tm` (Andrew Wade, Aug 2025,
port of O'Rear's zf2.nql) and `prov` is the Hilbert-style system documented at the top of
`ext/sorear-mtm/machines/2017-zf-sorear-748/zf2.nql` (Tarski S2 variant + EXT/REP/POW/UNI/INF, ZF without
regularity and choice). `wel v0 v0` = "v_0 e. v_0", wff code 1, the canonical contradiction the machine looks for.

Trust surface for a reviewer: busycoq's TM.v, the literal transition table (checked against zf2.tm by
tools/ + a decidable-equality `vm_compute` in Coq), the definition of `prov` (compare with zf2.nql's
documentation), and the theorem statement.

## Machine anatomy (verified by tools/crosscheck.py: 3921 ops, 0 mismatches)

* 69 framework states: boot, register ops (1.inc 1.sel 1.decnz, 2.ret1/2), dispatch (4.*, 5.root),
  IP arithmetic (6.break.k, 6.continue.k), register chains (3.<reg>.inc / 3.<reg>.decnz).
* 324 decision-DAG states = program: binary tree of cons cells with sharing. Node reads an IP bit:
  0 -> car, 1 -> cdr. Leaves: inc r, decnz r, break k, continue k, halt (all break/continue leaves in zf2
  sit in cdr position with k >= 1).
* Tape layout at a dispatch (head on first IP bit, state main().0):

      0^inf 1 P 1^j 0^g B 0^inf

  P = IP bits (MSB first, implicit trailing zeros), j = chain ones (selector moves done so far for the
  current register op), g >= 3 gap, B = register file: registers are runs 1^(v+1) separated by single 0,
  an optional `00` marks the selected register, register k (declaration order) is the (k+1)-th run from the
  RIGHT; to the left sit ~133 junk runs written by boot (never touched).
* Register op on register k takes k+2 dispatch cycles: cycles 1..k+1 each do one `1.sel` (selector moves
  one register left, chain ones j += 1), cycle k+2 reads k+1 ones and performs the op, clears the ones,
  and increments P.  `decnz` shrinks the register file from the left by one cell (gap g += 1); inc/sel
  keep its extent.  Wade's README: there is NO check that the IP fits in the gap -> proof obligation.
* Path arithmetic (bit list, increment at the right end):
    advance      P := P + 1          (overflow of 1^m: marker moves left; equivalent to P := [])
    break k      P := inc (strip_zeros k P)    strip bits from the right until k zeros removed
    continue k   P := strip_ones k P
    decnz on 0   break 1
* Boot: ~39.8k steps, ends at main().0 with P = [], all registers 0, gap g0 (measured, >= 19).
* Max tree depth 136, max run of car edges 9 (so the IP never has 10 consecutive zeros before the leaf;
  dispatch finds the IP start by counting zeros leftwards).

## Layers

    L0  Logic.v   wffs, Cantor pairing, wff codes (nql numbering), `prov : wff -> Prop`.
    L1  Enum.v    abstract enumerator = functional version of main() over 8 nat registers (O'Rear spec);
                  THEOREM: (exists n, enum_halts_in n) <-> prov (wel v0 v0).  Pure logic, no TM.
    L2  Prog.v    the concrete DAG (generated: ZF2Dag.v) refines the abstract step: one iteration of main
                  in the structured big-step semantics = one abstract step (scratch regs return to 0).
    L3  Sim.v     TM framework simulates the RM path semantics, generically in the DAG, under the gap
                  condition; boot lemma; IP-space safety (prefix by vm_compute on the RM + bound 136+12+3).
    RM  RM.v      shared interface: programs, path small-step semantics, structured big-step semantics;
        RMEquiv.v their equivalence (generic).

Final: halts tm c0 <-> (RM from ([],0..0) reaches halt) <-> (exists n, big-step iterate n halts)
       <-> (exists n, abstract enum halts) <-> prov (wel v0 v0).

## Conventions
* Registers: prooflist 0, nextproof 1, topwff 2, wffstack 3, axiomcode 4, param1 5, param2 6, param3 7,
  scratch1 8, scratch2 9, scratch3 10.
* Node indices in ZF2Dag.v: generated by tools/gen_coq_dag.py from zf2.tm (name table kept as comments).
* Build: `python coq/build.py File.v` (coqc 8.20, -Q BusyCoq / -Q ZF).
