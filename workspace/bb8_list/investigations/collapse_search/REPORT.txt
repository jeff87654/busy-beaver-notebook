0. VERDICT
----------
NEGATIVE for every target.  No (n-1)-state machine reproduces any target, literally or at the macro level.
  (a) h003 -> 8 states:   no collapse.  No 8-state machine with the champion engine shows more than 2 escalations and halts.
                          M8 and its 4 twins are the best.
  (b) C7 + twins -> 8:    no collapse.  The same 8-state family applies, so the same answer.
  (c) n1 -> 9 states:     no collapse.  J is a halting peek (J1 = E1), and I is an irreducible sweeper.
  (d) T12a -> 11 states:  no collapse.  K and L are halting peeks; best near-misses are n1 itself.
      M8 -> 7 states:     no collapse.  The best near-miss is the BB(7) champion itself (E0 = halt).
Controls:
  * M8 FOUND from C04: yes.  It is the only one of 499,305 C04 candidates that passes all 63 starts.
  * A synthetic n1 with a split sweeper collapses back to exactly n1: 66/66 starts.
  * Negative controls: 30 random C04 candidates pass 0 starts.  Over all screens, no non-trivial candidate passed every
    start (only the parent copies of the controls and the relocation artefacts of sec. 3).
Nothing record-beating: OPEN_CANDIDATES.txt is unchanged.

Structural reason (slot budget, holds for all five targets).  Every target uses ALL its non-halt slots in the profiled
worlds (bisim "unused slots: -"; T12a: K1 unused, the halt).  An (n-1)-state table has 2 fewer slots and still needs a halt.
So a collapse must remove >= 2 used behaviours (one for M8 -> 7 / T12a -> 11).  There are only two ways to do that:
  * a relay state, whose entries net to one step (C04's G, found by the literal screen);
  * two states whose used slots agree after merging.
The literal screen finds no relay in any target, and the bisim pass finds no compatible pair.  Every "NEAR" pair is a
state that agrees with another except on its halt slot (a halting peek):
  * n1 J ~ E (J1 = E1 = 0LC; J0 halts, E0 = 1LI);
  * M8 H ~ F (H0 = F0 = 1RG; H1 halts, F1 = 1LD);
  * T12a J ~ E and L ~ K.
Merging away a peek removes the only halt.

1. METHOD AND TOOLS (src/)
--------------------------
cand.py   Candidate generator, n -> n-1 states (start state A is never deleted; every candidate must keep >= 1 halt slot):
  D  X     Delete X.  Every incoming transition becomes any (w,d,T) with T kept, or halt (4(n-1)+1 options each).
  DR X Y   Delete X.  Incoming transitions are retargeted to Y with any (w,d).  Y's two slots are each either unchanged or
           any of the 4(n-1)+1 options (Y absorbs X).  Only when in(X) <= 3.
  M  X Y   Merge X and Y.  Each slot is taken from X or Y, or, for at most one slot, any option.  (M is nearly a subset of DR.)
  Exact duplicates are removed.  Each candidate carries a state MAP (parent -> candidate) used to start it in the parent's
  configurations.
cfollow.cpp (cfollow3.exe = current build; cfollow.exe / cfollow2.exe are older builds used by the first runs).  Modes:
  lit    Literal runs from a battery of START configurations.  Each run records EDGE MOMENTS: the head is on a 0 next
         to the outermost 1, and the moment stores a full-tape hash.  A candidate passes a start if its moment sequence
         matches the parent's with relay tolerance (<= 3 skipped moments per side at a mismatch) and it halts iff the
         parent halts.  The run aborts online at the first mismatch, after 2 failed starts, or after a moment gap more
         than twice the parent's.  Cost: about 2.5 ms per candidate.
  world  Jump world, a port of hsim's champion CL jump with R := Rdef for every clear.  Reports escalations
         (new-max-K clears), CL list, halt and ones.
  dump / ldump   Write start configurations: after every jump of a jump world, or every E-th literal edge moment.
  prof   Slot-use counts and the entry context of each state, for the bisimulation pass.
bisim.py   Observed-behaviour merge test over prof outputs.  COMPATIBLE: the used slots agree modulo X~Y.  NEAR: they
           conflict on <= 2 events per profiled run.
bform.py   n1-style B-form starts [L|A] -> tape.  Verified against literal n1 at steps 6447 and 48159.
s8sum.py   World summary.  nearmiss.py: ranks lit output.  canon.py: BFS relabelling.
runseq.sh / launch.ps1   Sequential Idle-priority launcher that logs PIDs.

START BATTERIES (faithful worlds = the parent's own macro configurations):
  champion-engine targets  Blank start, plus the configuration right after every CL jump of the parent's jump world with
                           R = 6, 30 and 126.  Counts: C04 63, h003 32, C7 63, twins 35-38, M8 63.  These include every
                           top branch, the exits, cascades and halts that occur in those worlds.  h003 was re-checked in
                           the residue-faithful world R = 366 (R* mod 3600) with N = 2e7.
  n1                       Blank start plus 65 B-forms: stage 0, the P1/P2/P4 shapes with small parameters, and endgame
                           forms with m = 0..6.
  T12a                     The n1 battery, plus 40 random endgame B-forms in which n1 halts at J0, i.e. where T12a
                           diverges from n1 (T12a halts at L1 in 19 of them and continues in 21).
  Literal horizon N = 2e6 parent steps per start.  A candidate gets 1.5N steps.

3. ARTEFACTS AND HOW THEY WERE RESOLVED
---------------------------------------
* Relocation pseudo-passes.  These are DR(X,Y) where X is the start state of every non-blank start (B for the champion
  targets, H for n1) and Y is rewritten into a copy of X.  The candidate then passes only the blank start, because all
  other starts are "unmapped".  Each was resolved:
  - h003, C7 and the twins: the canonical twin is "D(I) with H0 -> xLB".  It is in the same list with a B-preserving map
    and failed.
  - n1: re-run with the corrected map 01234567.8; it fails at moment 2.
* The first set8 run crashed (bad_alloc on a runaway tape).  A tape-width cap was added and rows 64-260 were rerun.
* The world-mode CL jump is valid only for an unmodified champion core.  That is why macro (world) comparison was used only
  on core-preserving candidates (set8).  Core-modifying candidates are judged by the literal screen, whose post-jump
  starts exercise the clears literally.

4. WHAT IS NOT COVERED (honest limits)
---------------------------------------
* The literal screen detects collapses that are tape-equal up to relays.  An "observational" collapse that differs from the
  parent only on configurations unreachable in the real run, through a residue invariant, would be rejected in the
  small-R worlds.  For h003/C7 the best non-core candidates fail at the class-independent far-left event, in both the small
  and the R = 366 worlds.  For n1 they fail at the first E0 event of every B-form.  So no such case is near.
* Macro twins with a DIFFERENT engine (not the champion core for h003/C7, not GH for n1) are outside any collapse notion.
  They were not searched.  For n1 the engine-preserving 9-state family (GH + 1 state) was closed earlier by the bb9 fw1
  search ("GH bases +1", see memory/bb9-fw1-search-status).  It was not re-run here.
* T12a: only deletions or merges of I, J, K, L were generated.  Deleting or rewriting a GH-core state fails at once for
  n1 (n1 lit: all 2.46M fail), and T12a = n1 on those starts.
* Transformations that need 2 deletions plus 1 new state were not enumerated.
