## Verdict

**The machine never halts.** It is a base-3 exponential counter with resets, and the reset values grow at
tetration rate. It has no sigma or score, so it is not a record candidate.

**Confidence: proved (Coq PASS).** `bb8_list/proofs/BB8_48631_1RB1RC.v` proves `Theorem nonhalt : ~ halts tm c0.`

## Configuration family

The head is in state B on the leftmost 0 shown. The tape is blank beyond both ends.

```
X(z, m) = 0^inf B> 0^z (10)^m 11111 0^inf
P(j, n) = X(4j+3, 2n) = 0^inf B> 000 (0000)^j (1010)^n 11111 0^inf      (Coq: P j n)
```

## Mechanism

1. **Bounce (Pass).** E sits on the blank cell left of a run of 1s. E0 writes 1. C, F and A then cross the
   1s in a period-3 cycle (C1 1RF, F1 1RA, A1 1RC). F0 turns the first 0 into 1, D1 walks back, and D0
   writes one more 1 at the left end. The run grows by 3 and loses one 0 on its right:
   `E> 1^(3a+1) 0` -> `E> 1^(3a+4)`.
2. **Start.** `B> 0000` becomes `E> 1111` in 9 steps. So z zeros become 3z-8 ones, which is 1 mod 3.
3. **End of a round (EndPair).** The last pass reaches the pairs: F reads the 1 of the first (10) pair, A fills
   its 0, and B, reading the next pair's 1, erases everything leftward (B1 0LB). So X(z, m+2) -> X(3z-2, m).
4. **Reset.** With no pairs left, two more bounces (R1, R2a) rebuild `11111` on the right. Then E1 starts the
   G/H sweep (G1 0LH, H1 1LG), which turns 3z+3 ones into (10)^((3z+3)/2). G0, A0 and two B1 steps then give
   X(3, (3z+3)/2).
5. **The only exits.**
   - The sweep ends in H on a blank (H0 undefined) exactly when the swept run has odd length, that is, when
     z is even.
   - An odd number of pairs ends in X(z, 1), which also halts.
   - Literal runs confirm both exits (`halt_exits.py`): X(4,0), X(6,0), ... halt, as do X(3,1), X(7,1) and
     X(19,1).
   - Writing z = 4j+3 and m = 2n excludes both exits: 3z-2 stays 3 mod 4, and (3z+3)/2 = 6j+6 is even.

## Recurrence and trajectory

- Starting from P(0, n) with n ≥ 1:
  - S0n gives P(1, n-1).
  - n-1 applications of Step1 follow. The first index goes J -> 3J+1, so after them it is (3^n - 1)/2.
  - Step0 then gives P(0, (3^(n+1) + 3)/2).
- In the X picture this is X(3, 2n) -> X(1 + 2·3^n, 0) -> X(3, 3^(n+1) + 3).

The trajectory from the blank tape:

| P(0, (3^(n+1)+3)/2) | ... |

So n grows by exponentiation at every reset (tetration rate). The machine goes through infinitely many resets
and never halts. The pipeline's 30,895 digits after 40 s fall inside the third phase. There z = 1 + 2·3^k with
k running up to about 1.6·10^20. Each of Quick_Sim's rule applications is a ×3 on z, which explains the rising
digits per loop.
