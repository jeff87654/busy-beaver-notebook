# BB(8) holdout, subtask 76450: `1RB0LG_0RC1RG_1LD1RF_1RE---_0LH1LC_1RA1LA_1RH0RE_0LF0RH`

Source: holdout of BB(8) subtask 76450 (mxdys enumerator @ a41db6c). Pipeline growth at 2 / 10 / 40 CPU-s was
4,260 / 9,895 / 21,449 digits of sigma, with digits per loop 1.76 -> 2.95 -> 4.07. All runs stopped at the time
limit.

## Verdict

**The machine never halts.** It is a doubling counter with a reset. Each reset turns the finished counter value into
the next counter length, so the tape grows at a tetration rate. The machine has no sigma and no score, so it is not a
BB(8) record candidate.

**Confidence: proved (Coq PASS).**
- `bb8_list/proofs/BB8_76450_1RB0LG.v` proves `Theorem nonhalt : ~ halts tm c0.`
- `python check.py BB8_76450_1RB0LG.v` prints
  `PASS ... never halts (machine-checked, no axioms)`. The table matches the machine string, and `Print Assumptions`
  reports "Closed under the global context". The file compiles in about 100 s.

**H1 variants `..._0LF1RA` and `..._0LF0LC`:** both are also proved non-halting. The same generator, rerun on each
variant table, produced Coq proofs with the same family and the same four rules. Both pass the same four checks as
`check.py` (see `check_variant.py`). The proof files are in `bb8_076450_1RB0LG0RC1RG/coq/`. H1 **is** read after the
family is reached: about 2.27M times in the first 60M steps. In every sampled read the context was `1 [H1] 0`, and
there all three tables give the same tape:

| machine | steps taken | result |
| --- | --- | --- |
| main: `H1=0RH` | 3 (`0RH`, `H0 0LF`, `F0 1RA`) | writes `1 1 0`, head moves to the 0 in state A |
| `H1=0LC` | 3 (`0LC`, `C1 1RF`, `F0 1RA`) | same |
| `H1=1RA` | 1 | same |

The `0LC` variant has exactly the same step counts as the main machine. The `1RA` variant is faster; for example, it
reaches the family at step 236 instead of 246.

## Configuration family

Tape words are written with `a = 10`, `b = 100` and `x = 1`, so `abb = 10100100` and `bab = 10010100`. In every
family member the head is in state A, on the blank cell just left of the word, with blank tape on both sides:

```
P(N,M) = 0^inf A>0 (abb)^N (bab)^M 1 0^inf        ones = 3N+3M+1
Q(N,M) = 0^inf A>0 (abb)^N 100 (bab)^M 1 0^inf    ones = 3N+3M+2
```

Note that `abb` and `bab` are rotations of the same 8-cell periodic word.

## Rules

All four rules hold for every N, M >= 0. None has a side condition or a halting branch.

| rule | statement | Coq lemma | literal check |
|---|---|---|---|
| RP | P(N, M+1) -> Q(2N+1, M) | `ruleRP` | 378/378 cases (N<=20, M<=8), and the same for both variants |
| RQ | Q(N, M+1) -> P(2N+2, M) | `ruleRQ` | same |
| ZP | P(N, 0) -> Q(2, N) | `ruleZP` | same |
| ZQ | Q(N, 0) -> Q(2, 2N+1) | `ruleZQ` | same |

The literal checks (`check_family.py`) simulate each start configuration with no acceleration until the next
left-edge state-A configuration that belongs to the family, then compare it with the prediction.

**Mechanism.** RP, RQ and ZQ all start the same way, `entry`:

```
0^inf A>0 (abb)^N 1001 r  -->+  V1(0, N, r),   where V1(j,k,r) = 0^inf G>0010 (01001010)^j (01010010)^k 010 r
```

- `bounce1`: V1(j, k+1, r) ->* V1(j+2, k, r). One block of the k-run is consumed per cycle, and each cycle is 8 visits
  to the left edge. The right sweep reads 3 cells past the k-run, and these are the fixed `010`.
- `bounce`, by induction on k: V1(j, k, r) ->* V1(j+2k, 0, r). This is the doubling.
- The three exits depend on what r starts with:
  - `exitP`: V1(j, 0, 0100 r) ->* `A>0 (abb)^(j+1) 100 r`.
  - `exitQ`: V1(j, 0, 0010100 r) ->* `A>0 (abb)^(j+2) r`.
  - `exitQ0`: V1(j, 0, 0^inf) ->* Q(2, j+1).
- ZP is a linear pass with no bounce.

**First family member.** From the blank tape the machine reaches Q(2,0) at step 246 without halting.

## Recurrence and growth

From Q(2,M), the rules RQ and RP alternate. After t of them the counter is x_t, with
x_0 = 2, 6, 13, 28, 57, 116, 233, 468, ... In closed form:

- x_t = (11·2^t − 4)/3 for t odd;
- x_t = (11·2^t − 5)/3 for t even.

What happens when the second parameter reaches 0 depends on the parity of M:

- **M odd:** the run ends at P(x_M, 0). ZP then gives Q(2, x_M), and x_M is even.
- **M even:** the run ends at Q(x_M, 0). ZQ then gives Q(2, 2x_M+1), which is odd.

So one super-step (two resets) maps an odd M to

```
M -> M' = (11·2^M − 4)/3  (even)  -> M'' = (22·2^M' − 7)/3  (odd)
```

Each reset exponentiates, so M grows like a tower of 2s.

The trajectory from the blank tape:
- Q(2,0) -> Q(2,5) -> ... -> P(116,0) -> Q(2,116) -> ... -> Q(2, M'') with M'' = (22·2^116 − 7)/3 ≈ 6.09·10^35.
- The next reset then gives a counter of about 10^(1.8·10^35).

The literal run `trajectory.js` confirms the start of this trajectory. It found 17 consecutive family configurations
in 400M steps, all as predicted and with 0 mismatches:

| step | configuration |
| --- | --- |
| 246 | Q(2,0) |
| 1,773 | Q(2,5) |
| 2,880 | P(6,4) |
| 585,480 | P(116,0) |
| 594,076 | Q(2,116) |
| 155,309,383 | P(1876,107) |

Each rule costs Θ(N²) steps.

**Reconciling the pipeline growth data.**
- Quick_Sim fuses RP and RQ into its "Iterated Rule 11", x -> 4x+22 with the counter falling by 2
  (`qs_prover2000.txt`). At most 10 applications per loop gives a ceiling of 10·log10(4) ≈ 6.02 digits per loop.
  That is why the observed 4.07 exceeds the ~3.01 ceiling of a single doubling rule.
- At 40 CPU-s the run was inside the super-step with counter 6.09·10^35. Quick_Sim shows the matching counter
  `01001010^609229498068086441747578235961824588`. Its 21,449 digits correspond to about 7·10^4 of the ~6·10^35
  doublings in that super-step.

## Record comparison

Because the machine never halts, it is irrelevant to BB(8) and to the 2↑¹¹2↑¹¹3 bar. I did not check it against
external lists; that check is moot for a non-halter.

State D is entered only through C0, rarely (5 times in steps 246 to 60M), and always reads 0. The halting transition D1
is never reached.

## Formal proof

`BB8_76450_1RB0LG.v` uses busycoq with Individual82 and Coq 8.20.1. Its contents:
- **Definitions:** `CP`, `CQ` and `V1` as above.
- **Crossing lemmas:** 11 lemmas over 8-cell blocks, each proved by induction. Two of them read and restore one
  context cell.
- **Rule lemmas:**
  - `bounce1`, which has 258 literal steps, 13 crossings and 7 `align_lpow` rotations;
  - `bounce`, by induction;
  - `entry`, `exitP`, `exitQ`, `exitQ0` and `ruleZP`;
  - the four rules.
- **Initial segment:** `init_reach` executes 246 literal steps to CQ 2 0.
- **Final theorem:** `progress_nonhalt_simple` is applied over `cfg : bool*nat*nat` with no side condition.

The per-phase scripts come from `planner8.py`, adapted from the control's planner. It mirrors busycoq's `execute` on
tapes with symbolic runs, derives the crossing lemmas by simulating a single block, and inserts `align_lpow` rotations
where the machine meets a run out of phase. `gen_coq.py` then writes the .v file. The planner is unreviewed, but it
only proposes the proof scripts; Coq checks every one of them.

## Open questions

- None for the verdict.
- Lesson for the pipeline: a digits-per-loop value above 3.01 does not imply super-doubling rules that could lead to
  halting. Here it comes from two doublings fused into one ×4 rule. The real growth, tetration through resets, comes
  from the Z-rules, and those have no halting branch.
