**Mechanism.** Every rule starts the same way: the first six steps (A0 B1 E1 C1 G1 H0) erase two cells of the word,
A0 B0 C0 restore them, and D1 sweeps back to the left end. Then the C0 D0 E1 cycle crawls right, turning
`C> 0 0 1` into `1 C> 0 0` (it reads one cell ahead), and looks at the cells after the 1-run:
- `0 0` (rule P): a short turn, then the A1/F1 pair sweeps left. It ends as A0 at the left end when the run has even
  length (P), or as F0 when it is odd. F0 G1 H0 then rebuild the left end as `1^5 0` (R).
- `0 1` (rule C): the turn ends in the leftward H1 C1 G1 sweep, which rewrites every 111 as 001. For length 6j+5 it
  reaches the left end in state H, builds `1^6`, and ends as A0. With other residues the sweep ends differently; for n ≡ 0, 1, 3, 4
  (mod 6) state G ends up reading a blank cell, and G0 halts.

## Recurrence

From W(0, M) the tail is consumed one cell per Wstep, and j follows j -> 2j+2, so j_t = 2^(t+1) − 2. After M steps
Wreset gives

```
W(0, M) ->* W(2^(M+1) − 2, 0) -> W(0, M'),    M' = 6(2^(M+1) − 2) + 7 = 12·2^M − 5.
```

The blank tape reaches W(0,3) at step 40. So M0 = 3, M1 = 91, M2 = 12·2^91 − 5 = 29710560942849126597578981371,
log10 M3 ≈ 8.94·10^27, and so on: a tower of 2s. Every W configuration has exactly one successor in the family, so
the machine never halts. G0 is never reached, and all 15 defined transitions are used (`usage_out.txt`); F0 is used
once in the first 40 steps and then only in rule R (once per reset).

**Literal trajectory** (`node trajectory.js 5000000000`, no acceleration, `trajectory_blank.txt`): it finds every
W configuration and checks that each is the predicted successor of the previous one, reached after exactly the
predicted number of steps. Result: 18 W configurations in 5·10^9 steps, 0 mismatches, from W(0,3) at step 40
through the first reset (W(14,0) at step 4,167 -> W(0,91) at step 4,579) up to W(16382,78) at step 4,295,135,436.
