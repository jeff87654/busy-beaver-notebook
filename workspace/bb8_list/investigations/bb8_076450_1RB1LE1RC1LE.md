# BB(8) holdout, subtask 76450: `1RB1LE_1RC1LE_0RD1RE_1LA---_1LG1RF_0LH0LG_1RH1LB_0RA0RG`

Source: holdout of BB(8) subtask 76450 (mxdys enumerator @ a41db6c). The mxdys NG/RWL/CPS pre-filter could not
decide it. Pipeline growth at 2 / 10 / 40 CPU-s was 7,060 / 11,553 / 27,122 digits at 1,408 / 3,275 / 4,568 loops
(5.01 -> 3.53 -> 5.94 digits per loop), stopped at the time limit. The undefined (halting) transition is D1.

## Verdict

**The machine never halts.** It is a doubling counter that pays for each doubling with 5 cells of a 1-tail. When the
tail runs out, the counter becomes the next tail, so the tape grows like a tower of 2s. It has no sigma, so it is
**not a BB(8) record candidate** and is irrelevant to the 2↑¹¹2↑¹¹3 bar.

**Confidence: proved (Coq PASS).**

  Coq 8.20.1, about 25 s to compile).
  - The conventional name `BB8_76450_1RB1LE.v` is already taken by a different machine, hence the longer name.
- `python check.py BB8_76450_1RB1LE_1RC1LE.v` prints (`bb8_076450_1RB1LE1RC1LE/check_py.out`):

- Every rule was also checked by exact literal simulation: 792 cases, 0 failures.
- A 1.5·10^9-step literal run from the blank tape confirms 16 consecutive family configurations with 0 mismatches.

## Configuration family (main machine)

Head in state E on the blank cell left of the word, blank tape to the left:

```
Ec(k, b, r) = 0^inf E>0 1 1 0 (1010)^k (01)^b r        = 0^inf E>0 1 (10)^a (01)^b r   with a = 2k+1
```

- a is the counter. It is always odd, so the planner uses 4-cell blocks.
- (01)^b is the work tape of the current round.
- r is the 1-tail `1^c 0^inf`. It is never read except at a round boundary.

## Rules

Phase rules (r arbitrary and never visited, unless it is 0^inf). All are proved for all k, b >= 0.

| rule | statement | literal check | Coq |
| --- | --- | --- | --- |
| IN | Ec(k, b+1, r) -> Ec(k+1, b, r) (a -> a+2) | 480/480 | `IN`, iterated in `INiter` |
| S5 | Ec(k, 0, 11111 r) -> Ec(2, 2k+2, r) (i.e. X(a,0) -> X(5, a+1)) | 120/120 | `S5`, `S5f` |
| S4 | Ec(k, 0, 1111 0^inf) -> Ec(2, 2k+1, 0^inf) | 40/40 | `S4`, `S4f` |
| Z0 | Ec(k, 0, 0^inf) -> Ec(1, 0, 1^(4k+5) 0^inf) (the counter becomes the tail, c = 2a+3) | 40/40 | `Z0`, `Z0f` |
| Z1 | Ec(k, 0, 1 0^inf) -> Ec(1, 0, 1^(4k+7) 0^inf) | 40/40 | not needed |

- The literal checks (`check_rules.py`) cover k < 40, b < 4, and three contexts each: 0^inf and two random words.
- They run with no acceleration to the first E0 configuration with a blank left side, and they compare the exact word.
- For arbitrary r they also require the same right-end alignment and that no cell of r is visited.

Family, with tail t = 0^inf or t = 1111 0^inf:

```
Fa(m, q, t) = Ec(5m+1, 0, (11111)^q t)          (a = 10m+3, i.e. a = 3 mod 5)
Fb(m)       = Ec(5m, 0, 0^inf)                  (a = 10m+1, i.e. a = 1 mod 5, empty tail)
```

| rule | statement | how | literal check | Coq |
| --- | --- | --- | --- | --- |
| T1 | Fa(m, q+1, t) -> Fa(2m+1, q, t) | S5, then IN x(10m+4) | 48/48 | `T1` |
| T2 | Fa(m, 0, 1111) -> Fb(2m+1) | S4, then IN x(10m+3) | 8/8 | `T2` |
| T3 | Fa(m, 0, empty) -> Fa(0, 4m+1, 1111) | Z0: 1^(20m+9) = (11111)^(4m+1) 1111 | 8/8 | `T3` |
| T4 | Fb(m) -> Fa(0, 4m+1, empty) | Z0: 1^(20m+5) = (11111)^(4m+1) | 8/8 | `T4` |

Why the halting residues never occur:
- The tail can run out with c = 2 or c = 3 left over. That case was not studied; it may lead to the halt.
- The counter's residue decides the leftover:
  - Rounds keep a = 3 (mod 5), because a -> 2a+7 fixes 3 mod 5.
  - So Z0 turns a tail with c = 0 into a new tail of length 2a+3 = 4 (mod 5).
  - That tail ends in an S4 step, after which a = 2a+5 = 1 (mod 5).
  - The next Z0 then gives a tail of length 2a+3 = 0 (mod 5).
- The leftover therefore alternates 4, 0, 4, 0, ... The parametrization by m makes this automatic, with no modular
  arithmetic in the proof.

Mechanism of IN (cell level):
1. The left end grows by two cells (E0 G0 H1 G1 B0 C1 E1 F0).
2. An H/G sweep crosses (1010)^k to the right, rewriting each 10 as 01.
3. At the first (01) pair of the work tape it turns (H0 A1 E0 G1).
4. A B/E/F/G sweep crosses back to the left over 4-cell blocks, restoring (1010).

The planner handles this as three crossing lemmas: H right over 1010, B left over 1010, and E left over 1010 -> 1111
(the last is used by Z0).

## Pipeline growth data explained

Quick_Sim uses 4-cell blocks and proves a rule that fuses about 40 rounds (doublings) per loop.
`qs_verbose3500_excerpt.txt` is from `Quick_Sim.py --recursive --max-loops=3500 --verbose-simulator`. It shows the
following:
- **Loops ≈ 140–1650** are the phase with tail 1^163829, i.e. 32765 doublings. The 2 CPU-s sample at loop 1,408 lies
  here.
- **Around loop 1700–2100** comes the tail exhaustion with c = 4, the S4 round and Z0.
  - The counter, about 10^9864, becomes the new tail `1111^(~10^9864)`.
  - The new counter restarts at a = 3.
- **Loops ≈ 2100–3000**: the nonzero count stays at about 9,865 digits (the tail) until the new counter overtakes it.
  This stall is the dip to 3.53 digits per loop at 10 CPU-s.
- **Later**, the counter's doublings dominate again, giving 5.94 digits per loop at 40 CPU-s.

So the non-monotone digits per loop is a phase reset, not a sign of halting or of super-tower growth.

Trajectory:
- The blank tape reaches VF(0,1,11) at step 109.
- It then runs VF(1,0,11) -> VF(0,5,111) -> VF(31,0,111) -> VF(0,125,11 010111) (step 266,743, tail 1^627 010111).

## Formal proofs

Both proof files are generated; their phase-lemma scripts come from `planner8.py` (copied unchanged from
`bb8_076450_1RB1LE0LC1RE/`, only the default machine differs).

`BB8_76450_1RB1LE_1RC1LE.v` (copy in `bb8_076450_1RB1LE1RC1LE/coq/`) is generated by `gen_coq.py` from

- `INiter` (induction on b); `S5f`, `S4f` and `Z0f` restate the phase rules on `Ec`.
- `T1`–`T4` on `Fa` and `Fb`; `init_reach` (115 literal steps).
- `nonhalt` via `multistep_nonhalt` and `progress_nonhalt_simple`. The index is `fam = FA m q (t : bool) | FB m`,
  and there is no side condition.
