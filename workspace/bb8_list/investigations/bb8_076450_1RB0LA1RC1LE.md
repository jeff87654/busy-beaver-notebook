## Verdict

**The machine never halts.** It is the doubling counter of `1RB1LE_1RC1LE_..._0RA0RG`
(`bb8_076450_1RB1LE1RC1LE.md`). Each doubling costs 5 cells of a 1-tail. When the tail runs out, the counter
becomes the next tail. Here the tail also carries a `01` end marker, and its leftover at exhaustion is always
1 (mod 5). The family closes after one reset, and the tape grows like a tower of 2s. There is no sigma, so the
machine is **not a BB(8) record candidate** and is irrelevant to the 2↑¹¹2↑¹¹3 bar.

## Relation to `1RB1LE_1RC1LE_0RD1RE_1LA---_1LG1RF_0LH0LG_1RH1LB_0RA0RG`

The two machines differ in **A1** (1LE -> 0LA), **F0** (0LH -> 1RH) and **H0** (0RA -> 1RA). A0 is unchanged.
- This machine has the related file's F0 value (1RH), so it has that file's F0 variant's even counter.
  - It differs from `1RB1LE_1RC1LE_..._1RH0LG_..._0RA0RG` only in A1 and H0.
  - The phase rules IN and S5 below are proved with the same statements as in that variant's proof.
- A1 and H0 act only at the right end of the counter: in the turn of each inner-loop step, and at tail exhaustion.
  - The turn takes a different route (H0 A1 A1 A1 A0 B0 C0 D0 A0), but IN and S5 have the same net effect.
  - They change the reset: the new tail is 1^(2a+3) followed by a `01` end marker that survives every later reset
    (rule E1w below).
- Residue question: the leftover residue does change. In the related main machine it alternates 4, 0, 4, 0 (mod 5).
  Here it is 1 (mod 5) every time, because the counter is a = 10m+4 at exhaustion and the new tail has 2a+3 cells.
  That leftover is handled by a proved rule, so D1 is not reachable.
- Where D1 could fire: D is entered only by C0, and C only by B0.
  - In the cell traces, C reads 0 only in the chain that follows H0.
  - In an IN turn, D then reads a cell that A1 has just set to 0.
  - In the reset (E1w), D reads blank tape beyond the old word.
  - These traces are illustration only; the Coq proof covers every case.

## Pipeline growth data explained

- This part is inference; I did not re-run Quick_Sim.
- Between the 2, 10 and 40 CPU-s samples the digit count rises by 12.04 digits per loop both times: (14455−6784)/637 and
  (28254−14455)/1146.
- 12.0 digits is 40 doublings (40·log10 2 = 12.04). This matches the related machine, where Quick_Sim was
  found to fuse about 40 rounds per loop.
- So all three samples lie inside the phase with q = 2^256 − 2, which has ~10^77 doublings: 28,254 digits is
  about 94,000 doublings into it.
- The rising average (3.20 -> 7.24) is the cost of the earlier short phases being averaged out. It is not a sign of
  anything faster than a tower.
