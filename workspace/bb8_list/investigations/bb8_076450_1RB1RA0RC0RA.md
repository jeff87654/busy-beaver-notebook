# BB(8) holdout, subtask 76450: `1RB1RA_0RC0RA_0LD1RC_1RE1LE_1LF0LG_1LB0RD_0LH1LF_1RF---`

Source: holdout of BB(8) subtask 76450 (mxdys enumerator @ a41db6c); the mxdys NG/RWL/CPS pre-filter could not
decide it. Pipeline growth at 2 / 10 / 40 CPU-s was 7,640 / 15,081 / 26,797 digits at 1,435 / 2,053 / 3,026 loops
(5.32 -> 7.35 -> 8.86 digits per loop), stopped at the time limit. The undefined (halting) transition is H1.

## Verdict

**The machine never halts.** It is an unbounded *digit-list counter*: a list of digits is counted down like a
mixed-radix counter whose refill values are the current (huge) counter value. That gives Ackermann-type growth, and
each time the list is used up it is rebuilt with about 4b digits. The only way to reach H1 is a reset that finds
exactly 4b+1 trailing zero digits. A proved bound (b > k at every reset) rules this out. The machine has no sigma, so
it is **not a BB(8) record candidate** and is irrelevant to the 2↑¹¹2↑¹¹3 bar.

## Configuration family

Configurations are written with the head in state B on the blank cell right of the word, and blank tape to the left:

```
K(ds; a; b) = 0^inf 1^d1 0 1^d2 0 ... 0 1^dn 0 1^a 0 1^b 0 1 B>0 0^inf      (ds = d1..dn, top digit first)
```

- The `1^d` runs are **digits**; a zero digit is an extra 0 in a gap.
- `a` is the inner counter and `b` is the accumulator.
- The trailing `0 1` is part of the machinery.
- Leading zero digits merge into the blank, so an all-zero list is the same as no digits.
- In Coq, `Kc ds a b` stores the digits last-first.

## Rules

Family rules (b ≥ 1 throughout; k = number of trailing zero digits, y+1 = the nearest nonzero digit):

| rule | statement | literal check (main) |
| --- | --- | --- |
| R1 (a ≥ 1) | K(ds; a; b) -> K(ds; a-1; 4b+4) | 960/960 |
| R2 (k = 0) | K(.., x+1; 0; b) -> K(.., x; 4b+3; 1) | 240/240 |
| R3 (1 ≤ k ≤ 4b) | K(.., y+1, 0^k; 0; b) -> K(.., y, 4b+3-k, 1^(k-1); 1; 1) | 123/123 |
| R4 (no digits) | K(; 0; b) -> K(2, 1^(4b); 1; 1) | 5/5 |
| halt (k = 4b+1) | H1 is reached | 6/6 halt as predicted |
| (k ≥ 4b+2) | K(.., y+1, 0^(k-4b-2), 2, 1^(4b); 1; 1) | 18/18 (never reached) |

The checks are in `check_rules.py`, with output in `check_rules_out.txt` and `check_rules_<variant>.json`:
- The family cases cover up to 3 digits (values 0-3), a = 0-3 and b = 1-5.
- Long zero blocks up to k = 4b+4 are included.
- Each case runs with no acceleration until the next family configuration.

**Mechanism** (machine-level phases, all proved in Coq; the numbers are the literal steps besides run crossings):
- **Transfer:** `TR1` (16 steps), then `TR2` once per 1 of the b-run. Each 1 of b becomes four 1s at the right end:
  `X 0 1^b 0 1 B>` -> `X 0 0 1^(4b) A>`.
- **Gap fill:** `ENTRY` (17 steps) sweeps left across the run to the gap left of it, then `LOOP` (8 steps) repeats.
  Each round moves one zero of the gap into a new `01` pair at the right end, at the cost of one 1 of the run:
  `l 0 0 1^(r+3) C> 0 rr -> l 0 1^(r+2) C> 0 1 0 rr`.
- **Ends of the fill:**
  - `FINAL` (11 steps): the gap has shrunk to one cell and the run still has ≥ 3 ones. The next 1 on the left is
    decremented, which gives R1 (the digit is the a-run), R2 or R3.
  - `END4b` (11 steps): the run is down to 2 while the gap is still open. This happens only on the blank tape, and
    gives R4.
  - Run 2 and gap 1 at the same time: the machine halts via E1 G0 H1. This is the k = 4b+1 case.
- The transitions G0 and H0 are used only in END4b and in the first 52 steps.

## Why it never halts

Clearing the last j+1 digits from the canonical refill `(1,...,1,W)` (a = b = 1, W ≥ 1) always ends with b ≥ W + j + 1:
- by induction on j (Coq lemma `EX`), with an inner induction on the digit being counted down (`IN`);
- R3 refills the block with `4b+3-k ≥ b+3`, so each count-down step at level j+1 increases b.

Every reset with k ≥ 1 trailing zero digits therefore has b > k. So R3 always applies (k ≤ 4b), and the halting case
k = 4b+1 (and the R4-like case) is never reached.

After R4 the list is `(2, 1^(4b))`, which is canonical. Clearing it gives the all-zero list, and R4 fires again. So
`Top B = K(2, 1^(4B+4); 1; 1)` has a successor `Top B'` for every B.

Each digit level adds one more iterated level on top of the level below it. Each rebuild then sets the number of
levels to about 4b. This is roughly f_(ω+1) growth in the fast-growing hierarchy, although it is irrelevant here since
there is no halt.

  it has done 13,987 R1 steps (b ×4 each, 0.602 digits per step, about 8,420 digits).
- The 5.3 -> 8.9 digits per loop is fused ×4 steps. It is not a sign of halting or of fast growth within the 40 s

## Formal proof

`gen_coq.py` generates all seven files from `coq_head.v.in` and `coq_tail.v.in` (`python gen_coq.py all coq`). Copies
are in `bb8_076450_1RB1RA0RC0RA/coq/`.
- **Crossing lemmas and phase lemmas.**
  - Four crossing lemmas (F left over 1s; A, C right over 1s; B right over `10`) are derived automatically.
  - The phase lemmas `TR1`, `TR2`, `ENTRY`, `LOOP`, `FINAL` and `END4b` get scripts from `planner8.py` (copied from
    earlier investigations, default machine changed). `script_to_coq`, `crossing_lemma` and `table` are copied
    unchanged into `coqgen_util.py`.
- **Hand-written part.**
  - `lft` and `Kc` encode the digit list.
  - `TRF` and `LOOPS` iterate the transfer and the fill loop, and `LOOPS_blank` is the fill loop on the blank tape.
  - `R1`, `RES` -> `R2`/`R3`, and `R4` are the family rules.
  - `R1iter`, `CH`, `EX` and `IN` clear digits with explicit lower bounds on b.
  - `TopZ` and `Top_step` give the cycle `Top B -->+ Top B'`.
  - `init_reach` is 52 literal steps (main).
  - `nonhalt` uses `multistep_nonhalt` twice and then `progress_nonhalt_simple` on `Top`.
