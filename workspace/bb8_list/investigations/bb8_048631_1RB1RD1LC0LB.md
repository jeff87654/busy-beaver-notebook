# BB(8) holdout 48631: `1RB1RD_1LC0LB_1RA0LB_0RE0RG_1RA1LF_1LG0LH_1RD0LF_1LF---`

Undefined (halting) transition: H1. Pipeline: 2 / 10 / 40 CPU-s = 9,740 / 19,054 / 35,123 digits.

## Verdict

**The machine (very probably) HALTS, at a modest size: sigma about 10^(5.6e4) (steps about 10^(1.1e5)).**
It is far below the BB(8) record bar 2^^11 ... (not a record candidate).

**Confidence: strong evidence, NOT proved.** No Coq file was written. The rules below come from the planner
(exact symbolic stepping, same semantics as busycoq's `step`) but the reset formulas were not turned into Coq.
The doubling-class signature is a red herring: the rising digits per loop come from the level-2 rule (x -> 81x+40).

## Structure

Cell-level, all configurations are `0^inf (01)^x A> R` (A-events; x -> 3x+1 per event). R is read by prefix rewrites;
two bounce loops (proved by `planner_b.py`, crossing lemmas FL/GR and GL/DR):
- TLE: `0^inf (10)^(a+2) E> (10)^(c+2) z -->+ (10)^(a+5) E> (10)^(c+1) z`
- TLD: `0^inf (01)^(a+2) D> (01)^(c+2) z -->+ (01)^(a+5) D> (01)^(c+1) z`

Two-digit stack machine (planner event maps, `ev6.py`, `t4.py`):
- Family X(P,Q) = `(01)^x A> (10)^P 11 (01)^Q T` (T = 00 10 01 00 10, later longer). Round of 4 events:
  X(P,Q; x) -> X(P-1,Q-1; 81x+40). Verified for P,Q symbolic.
- Family Z(A,B) = `(10)^A 0 (10)^B T'`: same round, Z(A,B;x) -> Z(A-1,B-1;81x+40).
- If the FIRST digit runs out first (X(P<=6, Q large), Z(A=2,3, B large)): planner reaches **H1 (halt)**.
- If the SECOND digit runs out first (Q or B in 1..3, other large): reset, x restarts at 1, and the tape becomes
  Z(N, other-B) with N = x after 4B+c events (~ 3^(4B+c) x), i.e. new pair (A',B') = (N, A-B).
  X(P,1) -> after 7 events `(10)^N 0 (10)^(P-1) 01001001001`; Z(A,2) -> N = 3^9 x + 4920.., pair (N, A-2).

## Trajectory (from Quick_Sim exact phase log, first 3 phases)
1. Phase 1: x=35 -> ... -> 29519 (7 half cycles, R = 10^2 11 01 00 10 style), reset.
2. Phase 2: digit 01^29522, again 7 half cycles to x=29519, reset.
3. Phase 3: X(29522, 29521) (P = Q+1..2), 29520 rounds, x ~ 81^29520: Q exhausts first (P-Q = 2, checked
   X(3,2) -> reset, not halt). Reset gives Z(N3, 2), N3 ~ 3^7 * 81^29520 ~ 10^(5.63e4).
4. Phase 4: Z(N3, 2): B=2 exhausts, new pair (A5, B5) = (~3^9 = 2e4, N3-2).
5. Phase 5: A5 << B5, so the FIRST digit exhausts first: A5 rounds (~2e4) then **HALT**.
   Final x ~ 81^A5 ~ 10^(3.8e4); the run (10)^B5 with B5 ~ 10^(5.63e4) is still on the tape at the halt,
   so sigma ~ 10^(5.6e4), steps ~ sigma^2 ~ 10^(1.1e5). (Exponent estimates are rough, alignments not calibrated.)
Quick_Sim (max 6000 loops, still in phase 3, P = Q+2 = 16410) never reaches this: about 10 rounds per loop.

## What is verified / gap
- Verified: TLE/TLD, the round maps, the halting endings (X(P,Q) P=1,3,4,5,6; Z(A,B) A=2,3) and the reset
  shapes, all by planner stepping on symbolic runs; A-event data by literal simulation (`lit.py`, `ev4.py`, `cyc.py`, 3n+1 law).
- Gap for a Coq proof (`Theorem halt`): exact constants of the reset maps for general residues (only B,Q=1,2,3
  computed), the pair recurrence B' = A-B with exact offsets, the phase 1-2 initial segment (blank -> X(29522,29521)),
  and generation of Coq (planner_b needs `absorb2`, `absorbr2`, `absorbrc2`, TLEs/TLDs lemmas; all of this is generated
  text, none written). Wide-open alternative: only the halting claim needs the exact ordering N3 >> A5, easy once constants exist.
- Endings not covered: X/Z with other small first-digit values were sampled (1..6), not all; a general proof needs
  the parity/alignment of each round.
