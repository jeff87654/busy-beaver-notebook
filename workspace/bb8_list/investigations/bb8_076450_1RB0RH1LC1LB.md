# BB(8) holdout, subtask 76450: `1RB0RH_1LC1LB_---1LD_0RE0LE_0LG1LF_1RE0LD_1RG0LA_1RA1RH`

Source: holdout of BB(8) subtask 76450 (mxdys enumerator @ a41db6c). The undefined (halting) transition is C0.
Pipeline growth at 2 / 10 / 40 CPU-s was 8,515 / 21,426 / 38,287 digits at 3,072 / 3,523 / 4,112 loops, with digits
per loop 2.77 -> 6.08 -> 9.31. All runs stopped at the time limit.

## Verdict

**The machine never halts. Confidence: proved (Coq PASS).**

- `proofs/BB8_76450_1RB0RH.v` proves `Theorem nonhalt : ~ halts tm c0.`
- `python check.py BB8_76450_1RB0RH.v` printed `PASS BB8_76450_1RB0RH.v: 1RB0RH_1LC1LB_---1LD_0RE0LE_0LG1LF_1RE0LD_1RG0LA_1RA1RH never halts (machine-checked, no axioms)`.
- It compiles in about 15 s.
- **It is not a record candidate.** Its only halting transition, C0, can never be reached from the blank tape.
  The fast growth comes from a multi-level counter that runs forever.

The proof does not use the counter at all. It uses a **local invariant**: a condition on the state and on a few
cells around the head, plus two regular conditions on the runs next to the head. The invariant holds on the blank
tape, every transition preserves it, and in state C it forces the scanned symbol to be 1.

## The invariant

Notation:
- s is the scanned cell. l0 and l1 are the first two cells left of the head (nearest first); r0 and r1 are the
  first two cells right of it.
- `Pl(l)`: reading leftwards from the head, the left side is `1^k 0 1 ...` (k >= 0).
- `Pr(w)`: reading rightwards, w is `1^k 0 x y ...` with x = 1 or y = 0 (k >= 0).

| state | invariant |
|---|---|
| A | (s=0 and (r0=0 or Pl(l))) or (s=1 and (l0=1 or Pr(r))) |
| B | (s=0 and l0=1) or (s=1 and Pl(l)) |
| C | s=1 |
| D | true |
| E | s=1 or l0=0 or r0=0 |
| F | r0=1 |
| G | (l0=1 and l1=1) or (s=1 and r1=0) or (s=0 and r0=0) or (s=0 and l0=1) |
| H | Pl(l) or Pr(s r) |

**Why it works.**
- C is entered only by B0 (`1LC`). B sweeps left over 1s after A0 (`1RB`), so halting needs a B sweep that ends
  on a 0 with another 0 to its left.
- Tracing backwards, the only route to that is E0 -> G1 -> A1 -> H0 -> A0 -> B1* -> B0 -> C0, starting from
  the local pattern `0 1 1 [E0] 1`. The first A1 writes the 0 at which B later stops, and the cell left of it is 0.
- Every other A1 in an H/A shift chain has an H-written 1 to its left. A G that has written at least two 1s
  leaves 1s to the left of A.
- E reads 0 only right after D:
  - D0 (`0RE`) leaves a 0 on E's left;
  - D1 (`0LE`) leaves a 0 on E's right;
  - F is entered only from E1 (`1LF`), so F0 (`1RE`) always puts E back on the 1 that E1 wrote.
- So the dangerous E0 never has 1s on both sides. The table above makes this inductive.
- All 15 defined transitions were checked by hand, and each is one case of `inv_step` in the Coq file.

**Empirical sanity checks** (`invcheck.js`, output in `invcheck_out.txt`):
- The invariant holds at each of the first 3,000,000 steps of the blank-tape run.
- From 20,000 random tapes that satisfy the invariant, in random states, each run of 5,000 steps kept the invariant
  and never halted.
- About 25% of random configurations violate the invariant. Random tapes and states do halt often (883 of 5,000 in
  `randtape.js`), so the invariant is doing real work.

## Formal proof (`proofs/BB8_76450_1RB0RH.v`)

- `Pl` and `Pr` are inductive predicates on `Stream Sym`. `Inv : Q * tape -> Prop` is the table above.
- `inv_step`: every configuration that satisfies `Inv` takes one step, to a configuration that satisfies `Inv`.
  - There are 16 cases on (state, symbol). The C0 case is refuted by `Inv` (it would need `0 = 1`).
  - The `Pl`/`Pr` cases use `inversion`.
- `inv_c0`: the blank tape satisfies `Inv`.
- `nonhalt` follows from busycoq's `progress_nonhalt` with `P := Inv`.
- `Print Assumptions nonhalt` reports "Closed under the global context".

## Configuration family and rules (context only, not needed for the proof)

At each visit of state A to a new leftmost cell, the tape is `0^inf A>0 0^z [n;k][m1;j1]...[mr;jr][2;0] 0^inf`.
- z = 3, sometimes 4.
- `[m;j]` = `0 1^m (001)^j`. The first segment has no leading 0; its zeros are counted in z.
- The final `[2;0]` = `0 11` is the tail.

Rules, checked by literal simulation to the next family configuration (`rulecheck.py`: 2,321 cases, 0 mismatches):

| rule | statement | cases |
|---|---|---|
| R1 | `[n;k+1] -> [n+9;k]` (n >= 1) | 180 |
| R2, n = 1 mod 3 (n >= 7) | `[n;0][m;j+1] -> [19;(n-7)/3][m+4;j]` | 2,052 in total over the three R2 residue classes |
| R2, n = 0 mod 3 | `[n;0][m;j+1] -> [2;0][1;n/3][m+4;j]` | |
| R2, n = 2 mod 3 | `[n;0][m;j+1] -> z4 [1;1][3;(n-2)/3][m+4;j]` | |
| T | `[n;0][2;0]` acts as R2 applied to n+4, and the tail is regenerated | 89 |

**Growth.**
- R1 applied k times after R2 turns `[n;0]` with n = 1 mod 3 into `[3n-2;0]`, and decrements the next segment.
  Each level-1 digit therefore triples n.
- The n = 0 and n = 2 cases, and the merges of exhausted segments `[m;0]` (which depend on m mod 3 and sometimes on
  the parity of n), insert new segments with counts of about n/3. The counter nests, at least at tetration rate.
- Literal run (`famrun.js`): `[19;15307][37;59][5;3][2;0]` at step 264,290,302, and
  `[19;45925][41;58][5;3][2;0]` at step 2,374,819,765.
- Quick_Sim at 3,000 loops already shows a level-1 digit count of about 6.5·10^35.
- The rising digits per loop reflect Quick_Sim fusing the ×3 steps. That growth is irrelevant to the verdict:
  whatever the counter does, C never reads 0.

## Record comparison and variants

- The machine never halts, so it scores nothing and is not a record candidate.
- C0 is the only undefined transition and it is unreachable. Every transition-level variant that only changes what
  C0 does behaves the same (it never runs).
- The proof does not depend on A1 = `0RH` or H1 = `1RH` beyond their actual actions.
- The superficially similar halting machine `1RB0LG_0LC0RH_---1LD_...` (proved to halt,
  `bb8_076450_1RB0LG0LC0RH.md`) is a different machine; its C0 is reachable.
