# BB(8) holdout `1RB0LD_0LC0RB_1RA1LC_0LH1RE_1LF0RF_0RB0LG_0RD0LD_1LE---`

Source: holdout of BB(8) subtask 76450 (mxdys enumerator @ a41db6c). Pipeline growth at 2 / 10 / 40 CPU-s:
2,874 / 11,091 / 19,863 digits of sigma, at 2,060 / 3,425 / 4,882 loops. Digits per loop were 1.40 -> 3.24 -> 4.07,
and every run was still going at the time limit.

## Verdict

**The machine never halts.** It is a two-digit counter with an overflow counter that only ever increases.
The tape grows at a tetration rate: the tower height rises by one for every two overflows. Because it never halts,
it has no sigma and no score, and it is **not a BB(8) record candidate**. The growth flag was a false positive.

**Confidence: proved (Coq PASS).**
- `bb8_list/proofs/BB8_76450_1RB0LD.v` (busycoq, Coq 8.20.1) proves `Theorem nonhalt : ~ halts tm c0.`
- `python check.py BB8_76450_1RB0LD.v` gives **PASS**: the table matches the machine string, and `Print Assumptions`
  reports "Closed under the global context".
- The file compiles in about 25 s.

**Community status.** The exact machine string gives no web hit. A search engine query found nothing, and the
wiki's own search is behind an anti-scraper page.

## Configuration family

The notation is plain binary. `[E0]` is the head, in state E, reading 0, and the tape is blank beyond both ends.

```
P(a1,b1,a2,b2,t) = 0^inf [E0] (10)^a1 11 0^b1 (10)^a2 11 0^b2 (10)^t 11 0^inf
```

- (a1, b1) is the units digit and (a2, b2) is the tens digit. Each 0^b is the digit's remaining room.
- t counts overflows. It is only ever incremented.
- The only halting transition is H reading 1. State H is entered only from D reading 0, and in every rule it is
  followed by H reading 0.

## Rules

Each rule is proved in Coq for **all** values of its variables and checked by literal simulation.

| rule | statement | mechanism |
|---|---|---|
| R1 | P(a, b+2, c, d, t) -> P(a+1, b+1, c, d, t) | B turns (10)^a into (11)^a going right, flips one 0, and G turns it back going left. |
| R2 | P(a+1, 1, c, d+2, t) -> P(1, 2a+2, c+1, d+1, t) | Units carry: E erases (11)^(a+1) to 0^(2a+2) with a moving marker 1, 5 steps per cell (`cross_EL`). |
| R3 | P(a+1, 1, c, 1, t) -> P(1, 2, a, 2c+3, t+1) | Overflow: the tens run is erased to 0^(2c+3), the units run (minus one block) becomes the new tens run, and t goes up by 1. |

Literal checks (`check_rules_literal.py 12`):
- Coverage: 10,368 instances in total. R1 has 6,912, and R2 and R3 have 1,728 each. The parameters run over
  0..11, with d, t in 0..3 or 0..2 where they are only carried along.
- Method: each instance was run with no acceleration until the exact right-hand tape appeared.
- Result: 0 failures, 0 halts, and at most 400 steps per instance.

**Invariant.** Let Q(a,b,c,d,t) = P(a+1, b+1, c, d+1, t). Exactly one rule applies to every member of Q:
- R1 when b ≥ 1;
- R2 when b = 0 and d ≥ 1;
- R3 when b = d = 0.

Each result is again in Q.

**Start.** From the blank tape, the machine reaches P(1,2,0,1,0) at step 83 and P(2,1,0,1,0) = Q(1,0,0,0,0) at step 110.
The Coq proof executes these 110 literal steps.

**Trajectory check.** `check_trajectory.js` runs 30M literal steps. It parses every left-end E visit and confirms that
each parsed visit follows from the previous one by the applicable rule. The results:
- 6,358 visits;
- 6,333 applications of R1, 21 of R2 and 3 of R3;
- 0 mismatches.

## Recurrence and growth

Start of each overflow cycle: P(1, 2, A, B, t).
1. R1, then R2, repeated B-1 times. Each round doubles the units digit.
2. Then R1 is applied 2^B - 1 times, followed by R3.

The result is (A, B) -> (2^B - 1, 2A + 2B + 1), with t -> t+1.

The values of (A, B, t) along the run, with the step at which each cycle starts where it was observed:

| A | B | t | step |
|---|---|---|---|
| 0 | 1 | 0 | 83 |
| 1 | 3 | 1 | 188 |
| 7 | 9 | 2 | 1,053 |
| 511 | 33 | 3 | 1,426,872 |
| 2^33 - 1 | 1089 | 4 | |
| 2^1089 - 1 | 2^34 + 2177 | 5 | |
| ≈ 2^(2^34) | ≈ 2^1090 | 6 | |

Hence B_{t+2} ≈ 2^(B_t + 1), a tower of 2s whose height grows by one every two overflows. The number of 1s is
a1 + a2 + t + 6. Each cycle costs roughly 4^B steps.

**Why the digits-per-loop signal passed the ~3.01 cap.** Quick_Sim uses 2-cell blocks, so one of its General rules
(`11^x ... 00^(y) -> 11^(4x+6) ... 00^(y-1)`, see `qs_prover.txt`) bundles two R2 carries. That is ×4 per
application, and up to 10 applications per loop gives a cap of about 6.02 digits per loop. There is still no rule
beyond doubling per carry. At 3,000 loops Quick_Sim was inside cycle t=5, with about 1.7e10 carries still to go
before the next overflow.

## Formal proof (`bb8_list/proofs/BB8_76450_1RB0LD.v`)

- **Crossing lemmas.** There are three, each proved by induction:
  - `cross_BR`: B> across (10)^n gives (11)^n.
  - `cross_GL`: <G across (11)^n gives (01)^n.
  - `cross_EL`: <E across (11)^n with a 1 on its right gives 1 0^(2n).
- **Rule lemmas.** `rule_R1`, `rule_R2` and `rule_R3` are `-->+` lemmas made of `execute`/`follow` scripts. The
  scripts were generated by `coq_scratch/gen_scripts.py`, the control's planner retargeted to this machine plus the
  special `cross_EL` step.
- **Normal form.** `finish_norm` extends the control's normal form with `lpow_add`, because busycoq's `step` splits
  runs of the form `[0]^^(n+n)`.
- **Assembly.** `init_reach` (110 steps) and `progress_nonhalt_simple` over Q complete the proof. No side conditions
  are needed.

## Open questions

None for this machine. Suggested pipeline note: the doubling-class ceiling depends on the block size Quick_Sim
chooses. Here the ceiling is about 6.02 digits per loop, because one 2-cell block bundles two carries. The flag
should compare against that ceiling, or inspect the multiplier of the General rule directly.
