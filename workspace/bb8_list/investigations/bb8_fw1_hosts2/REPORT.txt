1. STRUCTURE (pairs.py, usage.py; literal a=0 events, 600 per base)
   * Every defined slot is used by the D/borrow engine. Exceptions: the halt slot; A0 in C2-C6 (used only at the start);
     A0 in C10 (used only by TOP and the start). So any one-new-state gadget that keeps the engine intact is a guard: a slot X is
     redirected to H, H copies the old target on the engine symbol and does something else on the other symbol s.
   * (X, s) pairs that occur only in rare events:
       A: none (TOP-ACC, collapse and EMPTY events use engine pairs only).
       B: 2 pairs per base (e.g. B1: A1 then 0, B0 then 0). They occur only in ODD-counter ABSORB (and in counter-less ABSORB, which never happens).
       C: 3 pairs per base, only in TOP (C10: 4).
   * Family B ABSORB parity is exact and 2-adic. Base TOP-ACC sum over one round: c_new = c0 + 6168 - n(n+6), with n = floor(c/2)+5
     and c0 = -1 or +1. This uses Y(1)=17, Y(2)=6137, and Y(j) = -7 mod 2^3069 for j>=3; bpar.py checks it exactly for n=1,2.
       B1/B3: first ABSORB c=16 (step ~1031). c = 0 mod 4 is invariant, so every ABSORB is even and odd-ABSORB hooks never fire.
       B2/B4: first ABSORB c=6151 (literal, step 50,443,737). The parity pattern is 1,1,0 repeating, so odd hooks fire at round 1.
   * Family C: at round ends y = -5 (2-adic), so every residue is fixed. The only data carried from round to round are the top
     value and the flag pattern, and the flag pattern only grows (one new flag per TOP). The halt test b <= K never fires.

4. WHY IT FAILS (the structural reason)
   * One new state cannot touch the engine. It acts only as a guard at a rare event (TOP / ABSORB). Its trigger is local:
     one cell after one slot. Every trigger available here is either always true at that event (halt at round 1) or tied to a
     2-adic residue that the dynamics fix (B1/B3: odd ABSORB never happens; B2/B4: it happens at round 1).
   * Across a round, the hosts carry only: the top value and a growing flag pattern (C); the counter c, which ABSORB consumes
     completely (B); the counter sublist (A). None of these is a quantity that a one-cell guard can decrement once per round
     and test for zero. Every modified rebuild found is a fixed-offset or fixed-prefix change of the same round map.
   * Two-state guards (9 states) only add a fixed action at the same event. The results have the same shape, so there is still
     no countdown.
   * An f_(w+1) halter on these hosts needs a gadget that keeps a separate unary counter through the full-list rebuild and
     decrements it per TOP/ABSORB (for B: ABSORB would have to split c instead of consuming it). That needs more than 2 states,
     plus engine-sharing slots, which this enumeration does not cover.

5. CAVEATS
   * Everything is rule-level. Batteries are finite: 80 engine events, residues mod 64 for y, c up to 62 for ABSORB.
     "Never halts" for fixed-form classes rests on the affine fits extrapolating.
   * Engine-modified variants (~808k at 8 states) were screened only from the blank tape (1e6 steps), as in bb8_fw1_redirect.
   * B variants with a changed start, or with NONSTD/TOPACC-MOD after the start (~3.6k at 9 states, ~120 at 8 states), were not
     followed symbolically to the end. They have no halting event in the battery and no late blank-tape halt.
