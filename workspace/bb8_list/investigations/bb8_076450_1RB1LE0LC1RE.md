# BB(8) holdout, subtask 76450: `1RB1LE_0LC1RE_0RA0LD_1RA1LC_1LF0RC_1RG1LC_0LH1LG_1LB---`

Source: holdout of BB(8) subtask 76450 (mxdys enumerator @ a41db6c). Pipeline growth at 2 / 10 / 40 CPU-s was
7,936 / 18,328 / 29,521 digits at 1,856 / 2,582 / 3,364 loops (4.28 -> 7.10 -> 8.78 digits per loop). All runs stopped
at the time limit. The undefined (halting) transition is H1.

## Verdict

**The machine never halts.** It is a tripling counter with a reset. Each reset turns the finished counter into the
length of the next counter's tail, so the tape grows at a tetration rate (a tower of 3s). It has no sigma, so it is
**not a BB(8) record candidate** and is irrelevant to the 2↑¹¹2↑¹¹3 bar.

**Confidence: proved (Coq PASS).**
- `bb8_list/proofs/BB8_76450_1RB1LE.v` proves `Theorem nonhalt : ~ halts tm c0.` (busycoq, Individual82,
  Coq 8.20.1, about 30 s to compile).
- `python check.py BB8_76450_1RB1LE.v` prints (`bb8_076450_1RB1LE0LC1RE/check_py.out`):
  `PASS BB8_76450_1RB1LE.v: 1RB1LE_0LC1RE_0RA0LD_1RA1LC_1LF0RC_1RG1LC_0LH1LG_1LB--- never halts (machine-checked, no axioms)`.
- Every rule is also checked by exact literal simulation (600 cases, 0 failures), all 400 recorded step counts match
  closed forms, and a literal run from the blank tape confirms the first 12 family configurations with exact step
  counts (see below).

## Configuration family

Head in state G on the blank cell just left of the word, blank tape to the left:

```
P(j, t, s) = 0^inf G>0 1^(6j+5) (01)^t S_s      S_0 = 0^inf,  S_1 = 1 1 0^inf
Y(n)       = 0^inf G>0 1^n 0^inf                (P(j,0,0) = Y(6j+5), P(j,0,1) = Y(6j+7))
```

`1^(6j+5)` is the counter and `(01)^t` the tail. The suffix `S_1 = 11` is left behind by one kind of reset.

- Pstep is R3 followed by R1 once per (01) pair (3j+4 times). Each R1 adds six 1s, so the counter goes
  6j+5 -> 3(6j+5)+14. P00 and Y4f work the same way on a blank right end.
- The literal checks (`check_rules.py`, output `check_rules_out.txt` and `check_rules.json`) run with no acceleration.
  For each cell rule they compare the exact word and require that no cell of r was visited, over 3 contexts each
  (empty and two random). `fit_steps.py` checks all 400 recorded step counts against the formulas above, with
  0 mismatches (`fit_steps.out`).

**Mechanism.**
- Every rule starts at the left end with G0 H0 B0 C0 A0, which extends the word by two cells.
- Then a rightward A0 B1 E1 C1 D0 crawl moves across the 1-run three cells per 5-step cycle. The planner handles
  it as the crossing `B> (111)^n`.
- The residue of the run length mod 3 decides what the crawl meets:
  - n = 0 (mod 3), followed by `01` (R1): the pair is absorbed and G sweeps left over the 1s (G1).
  - n = 2 (mod 3), followed by `0` (R3, Y5): E0 F1 start a leftward C1/D1 sweep, which rewrites `11` as `10` and
    turns the run into the new `(01)` tail.
  - At a blank right end (Y4, Y3, Y1): a similar leftward C/D sweep. The residue and parity decide how the left end is
    rebuilt.
- The counter only takes the residues 5, 4, 3 and 1 (mod 6) at a blank end:
  - 5 -> 4 via P00;
  - 4 -> 3 via Y4f;
  - 3 -> P(1, ·, 1), which ends at 1 (mod 6) via P01;
  - 1 -> P(1, ·, 0), which ends at 5 (mod 6).
- The residues 0 and 2 (mod 6), whose behaviour is not covered, are therefore never reached. H1 never fires.

## Recurrence

A phase starting at P(1, T, s) applies Pstep T times, with n + 7 -> 3(n + 7). It ends at counter length
n = 18·3^T − 7 = 6j + 5, j = 3^(T+1) − 2. Then:

```
s = 0:  P(j,0,0) -> Y(18j+28) -> Y(54j+93) -> P(1, 27j+46, 1) = P(1, 3^(T+4) - 8, 1)
s = 1:  P(j,0,1) = Y(6j+7)                 -> P(1, 3j+3, 0)   = P(1, 3^(T+2) - 3, 0)
```

- After that, T3 = 3^(T2+2) − 3 ≈ 10^(1.09·10^13), and so on: a tower of 3s (`sizes.py`, `sizes.out`).
- Every family configuration has exactly one successor in the family, so the machine never halts.
- All 15 defined transitions are used (`usage_out.txt`), and H1 never is.

## Pipeline growth data

At 2000 loops, Quick_Sim (`qs_prover2000.txt`, `--recursive --max-loops=2000 --verbose-prover`, 15 s) is in phase 2,
P(1, T2, 1):
- Its tail is `101010^7625597484980`, and 3·7,625,597,484,980 = T2 − 13, so it matches T2 = 3^28 − 8 exactly.
- Its `Iterated Rule 14` is `111111^x ... 101010^(y) -> 111111^(27x+182) ... 101010^(y-1)`. This fuses three Psteps
  (×3 each) into ×27, so the cap is 10·log10(27) ≈ 14.3 digits per loop.
- The observed 8.78 digits per loop is therefore fused tripling, not super-exponential growth. The 29,521 digits at
  40 CPU-s correspond to about 62,000 of the ≈2.3·10^13 Psteps in phase 2.
