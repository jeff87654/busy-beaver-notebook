## Answers to the questions asked

- **Is it a genuine digit list? Yes.** The scanner's family is real, but its fitted R3 is wrong beyond one zero digit (the same pitfall as in the 891716 report).
  The true rules (below) have **no halting boundary**: every configuration with a positive nearest digit, or with b >= 1, has a successor, so non-halting
  follows from totality of five rules. The only undefined transition (H0) is never read.
- **What happens when the list is used up? It rebuilds, it never halts.** R4: `K(0^n; 0; b) -> K(2^b; 2; 0)`, i.e. b+1 digits 2 (a = 2, accumulator 0). The
  rebuilt list is processed by the same rules, so the machine is an unbounded tower of epochs (first epoch: b = 14, the list of 14 twos + a = 2 is rebuilt at literal
  step ~11,800; later epochs have astronomically large b). The list length is the previous accumulator, so growth is Ackermann/tower type.
- **A halt after a rebuild would be a record: there is none.** Totality holds for every F W b with the invariant, including every rebuilt list.
- **The n-gram prover failure is expected**: the digits and the accumulator are unbounded and the cost of R3 is bilinear; no finite window language closes.

## Configuration family and rules (all verified)

Tape (head D on the blank right of everything, nothing to the right; orientation R):
`0^inf (10)^d_n 00 ... (10)^d_1 00 (10)^a 00 (10)^(2b+2) D>`. Write W = [a, d_1, ..., d_n] (nearest the head first). F(W, b) in the Coq file.
Leading zero digits merge into the blank. The scanner template is `R,D,P=-,u=10,s=00,d=1d+0,b=2b+1,S=10`.

Let W = 0^j ++ (y+1) :: t, with j = the number of leading zero digits (a counts):

| rule | condition | F(W, b) -->+ |
| --- | --- | --- |
| R1 | j = 0, W = (a+1) :: t | F(a :: t, b+1) |
| R3A (j = 1 is the scanner's R2) | j >= 1, j <= b | F(2^(j-1) ++ [2(b-j+2), y] ++ t, 0) |
| R3B | j = b+1 | F(2^b ++ [y+3] ++ t, 0) |
| R3C | j >= b+2 | F(2^(b+1) ++ 0^(j-b-2) ++ (y+1) :: t, 0) |
| R4 | W all zero (any j >= 0), b >= 1 | F(2^(b+1), 0) |

Invariant: the head digit is positive, or b >= 1 (all results have head digit >= 2 or b+1 >= 1). From the blank tape the first family configuration is
`F([2;2], 0)` (K(2; 2; 0), step 330 for the representative; 276..336 for the variants; `init` in the files).

Dynamics: each unit of a adds one to b (R1); a digit decrement with a = 0 sets a := 2b+2 and b := 0, so a full R1 run doubles b (b -> 2b+2); a zero digit is refilled by R3A with
2(b-j+2) followed by j-1 twos; R3B/R3C are the degenerate cases where b runs out before the zeros do; R4 rebuilds b+1 twos from the accumulator.

## Formal proof structure (what is machine-checked)

Generated by `gen_fam.py` on top of `bb8_list/autoproof` (engine.py / coqgen.py), following the 891716 proof (`BB8_891716_1RB0LD.v`):
- **Machine-level, generated and proved automatically** (no hand-written phases): `R1m` (one nested-free loop on b), the **pass lemma** `Pass`:
  `PS (S z) (S c) d l -->+ PS z c (S d) l` with `PS z c d l = 1 (10)^(c+1) 0^(z+2) l <C 1 (101)^d` (one zero turned into a marker, one unit of the b-run consumed,
  one deposit (101) appended at the far end), its blank-left twin `PassB` (used-up list), the start segments `R3A0/R3B0/R3C0/R4_0` (3 literal steps to the first pass start)
  and the end segments `R3A1/R3B1/R3C1/R4_1` (last passes + the transfer loop that turns the d deposits into digits 2).
- **Hand-written glue** (`glue_fam.v.in`, ~120 lines): pass iteration `PassIt`/`PassItB` by induction on the number of passes (one pass per zero cell, so about 2j+2 passes for j zero digits),
  the doubling lemmas `[1;0]^^(2n) = [1;0;1;0]^^n` etc., and the four chains `R3Am`, `R3Bm`, `R3Cm`, `R4m`.
  Pass counts: R3A 2k+2 passes from `PS (2k+2) (2k+2r+4) 0` to `PS 0 (2r+2) (2k+2)`; R3B and R3C 2c+4 passes (R3C leaves `PS (2m+2) 0 (2c+4)`); R4 2c+4 passes.
- **Family level** (`family_fam.v.in`): `lft`, `F`, the rules `R1F, R3AF, R3BF, R3CF, R4F`, `step_total` (the invariant `inv W b` gives a successor, no halting case),
  `init` (literal start-up by `execute`) and `nonhalt` by `multistep_nonhalt` + `progress_nonhalt`.
- autoproof was **not modified**. Two small post-processing details in `gen_fam.py`: the `c = 0` branch of `PassB` needs `repeat rewrite zero_const` before the first rule application.
- Compile times: ~70 s on an idle machine; 230-1600 s at Idle/BelowNormal priority on this loaded PC.
