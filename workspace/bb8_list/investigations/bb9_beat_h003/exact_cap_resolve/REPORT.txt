2. ROOT CAUSE OF CAP-SENSITIVITY IN strict_tables_cap.cpp
================================================================================
In strict_tables_cap.cpp, try_accel_m5 collapses a sequence of s_digits even
runs 1^(2*d_j) 00 (d_j >= 0) and an odd terminator 1^(2*d_odd + 1) at state E:
  - True mathematical collapse:
      u = 2*A,   where   2*A + 3 = 5 * 3^(2 + sum_{j=1}^{s_digits} (2*d_j + 1) + 2*d_odd).
    Because 2*d_j + 1 is ALWAYS ODD for every even digit d_j >= 0 (including
    0-digits 0000 where d_j = 0 and 2*d_j + 1 = 1), every even digit multiplies
    (2*A + 3) by an odd power of 3 (congruent to -1 mod 4). Therefore, for any
    tower of height >= 2:
      (i)   u == -3 (mod 3^b) for all b <= 20   (A == -3/2 mod 3^b),
      (ii)  u ==  0 (mod 6),
      (iii) u == 2 - 2*P (mod 4), where P = (sum_even + d_odd) mod 2, so
            A = u/2 == 1 + P (mod 4)  (A == 1 mod 4 if P=0; A == 2 mod 4 if P=1).
  - At CAPX = 0 and k < 46 (s_digits < 44), strict_tables_cap.cpp uses
    base_u = 60, mapping u_ll = 0, 2, 1, 3 (mod 4) to u_cap = 60, 66, 69, 63,
    which preserves the EXACT mathematical (mod 4, mod 6) residue of every M5
    and M1 collapse.

Three distinct mechanisms in strict_tables_cap.cpp caused spurious variation:
  (A) Artificial slope for k >= 46 (Group 1 false R = 8):
      Line 148 of strict_tables_cap.cpp sets
        base_u = 6 * ((s_digits + 10) / 6 + 1)   (rounded up to a multiple of 12),
      with base_u = 60 for s_digits < 44 (k < 46), growing linearly with slope
      +12 per Delta_k = 6 for k >= 46. When solve_nofit300.py fit an affine law
      to k in [44, 300] at CAPX = 0, it captured this artificial base_u slope,
      producing the false R = 8 result on Group 1.
  (B) Mod-4 parity inversion at odd multiples of 6 (CAPX = 6, 18, 30, ...):
      Adding CAPX == 6 (mod 12) adds 6 == 2 (mod 4) to u_cap, flipping A_cap
      between 1 and 2 (mod 4) and inverting every subsequent M1 parity branch.
  (C) Gap-guard overflow at large CAPX (Group 5 false 'G' at CAPX = 120):
      At CAPX = 120, u_cap = 180..186 exceeds max_allowed_gap = 2*k + 28 for
      57 <= k <= 78, causing false 'G' aborts on Group 5.
