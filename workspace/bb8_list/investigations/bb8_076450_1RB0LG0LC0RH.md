# BB(8) holdout, subtask 76450: `1RB0LG_0LC0RH_---1LD_0RD1LE_1RF0LC_1RG1LG_1LA1LF_1RA1RH`

Source: holdout of BB(8) subtask 76450 (mxdys enumerator @ a41db6c). Pipeline growth at 2 / 10 / 40 CPU-s was
11,392 / 27,322 / 40,471 digits at 4,306 / 4,747 / 5,111 loops, with digits per loop 2.65 -> 5.76 -> 7.92. All runs
stopped at the time limit. The undefined (halting) transition is C0.

## Verdict

**The machine halts.**
- sigma = (2·N6 + 5)/3 ≈ 10↑↑5.1625, that is 10^10^10^(2.6500059·10^28).
- steps = (3/5)·sigma²·(1 + o(1)), which is also ≈ 10↑↑5.1625.
- N6 is the sixth term of the exponential Collatz-like map described below.

**It is not a record candidate.** 10↑↑5.17 is far below 2↑¹¹2↑¹¹3, and even below 2↑↑↑4 = 2↑↑65536.

## Configuration families

In both families the head is in state A on the blank cell just left of the word, and the tape is blank elsewhere:

```
X(a,b,c) = 0^inf A> 0 1^a 0 1^b 0 1 (011)^c 0^inf        (a odd; every reachable X has a = 1 mod 4)
Y(n)     = 0^inf A> 0 1^n 0^inf                           (Y(0) is the blank tape)
```

the first configuration in X or Y (or a halt), which was compared with the prediction (`check_rules.py 61 30 10 60`).
All rules hold for every parameter value in Coq.

- **Total:** 11,125 cases, 0 mismatches.
- **Step counts:** the formulas were fitted exactly (`fit_steps.py`) and reproduce every case.
- **Scope of R1:** R1 needs a odd. With a even the F/G sweep lands on the other parity and the machine leaves the
  family. Every reachable X has odd a.

**Mechanism.**
- R1 and R2: H sweeps right through 1^a, and A erases one cell of the next run. The F/G pair (period 2) then sweeps
  back left and adds 4 ones.
- R4, R5 and R6: from Y(n) the machine walks to the right end, then B0 starts a leftward C/D/E sweep. That sweep has
  period 3 and turns 111 into 110. Which state meets the left end depends on n mod 3:
  - state C (n = 2 mod 3): C0 is undefined, so the machine halts;
  - states D and E (n = 0 or 1 mod 3): a new X configuration is built.

## Recurrence

Let B(c,b) = g^c(b) with g(b) = 4b+5, so that 3·B(c,b) + 5 = 4^c·(3b+5).
- R1 applied b times, followed by R2, gives X(1, b, c+1) ->* X(1, 4b+5, c).
- Hence X(1, b, c) ->* X(1, B(c,b), 0) ->* Y(4·B(c,b) + 9).

This gives the Y-map f, with two cases:

```
YA: Y(3k+3)  ->* Y(4·B(k,5)  + 9) = Y((20·4^(k+1) + 7)/3)
YB: Y(3m+13) ->* Y(4·B(m,33) + 9) = Y((416·4^m + 7)/3)
    Y(3k+2)  ->  halt
```

`node trajectory.js ymap 0 20` checks f literally for n = 0..20, with 0 mismatches. For example, Y(18) -> Y(27309)
takes 198,874,495 steps.

**Trajectory from the blank tape.**
- Literal: Y(0) -> Y(4) at step 12 -> Y(13) at 80 -> Y(141) at 5,382 (= YB with m=0).
- The blank-tape run (`trajectory.js blank`, 3·10^9 steps) parsed 35,599 consecutive family configurations. Every one
  follows from the previous by R1 to R5, with 0 mismatches. It reached X(105845, 844, 40).

- The N3 row comes from YA with k = 46, and log10 N4 = 2.65000593534824·10^28.
- The residues of N4 to N6 need only N3 mod 81, because g^(3^j) is the identity mod 3^j:
  - B(46,5) = 34 (mod 81), so M3 = 17 (mod 27);
  - B(M3,33) = 16 (mod 27), so M4 = 2 (mod 9);
  - B(M4,33) = 4 (mod 9), so M5 = 1 (mod 3);
  - B(M5,33) = 2 (mod 3), so N6 = 2 (mod 3).
- This arithmetic was done three ways, and all three agree:
  - in Coq (`step3` to `step6`);
  - in `arith.py`, both with exponent reduction mod 3^(e-1) and by iterating g mod 3^e;
  - independently in `ymap.py`, to 3^40.

**Why it halts.** Each YB or YA step is decided by a fresh residue. The chance of halting at each step is heuristically
1/3, and this machine survives three big steps (N3, N4, N5) before N6 = 2 (mod 3).
