## Configuration family

Head in state A on the blank cell just left of the word, blank tape on both sides:

```
S(n,k,j) = 0^inf A>0 1^n (011)^k 0 0 1^j 0^inf        (n even)
```

- n is the counter, k the number of unread (011) digits, j the number of resets so far (it is only carried).

## Rules

All rules hold for an arbitrary right context r that is never visited, and for all parameter values shown.

| rule | statement | steps | literal check | Coq |
| --- | --- | --- | --- | --- |
| O (p>=0) | A>0 1^(2p+1) 0 r -> A>0 1^(2p+5) r | 8p+9 | 360/360 | `O1` |
| E (p>=1) | A>0 1^(2p) 011 r -> A>0 1 0^(2p-1) 1^5 r | 8p+2 | 357/357 | `Erule` |
| Z4 (q>=0) | A>0 1^(6q+4) 00 r -> A>0 1^4 (011)^(2q+1) 001 r | 24q+22 | 120/120 | `Z4raw`, `Z4` |
| Z0 (q>=0) | A>0 1^(6q+6) 00 r -> A>0 1 00 1^5 (011)^(2q) 001 r | 24q+37 | 120/120 | `Z0raw`, `Z0` |
| Z2 (q>=0) | A>0 1^(6q+2) 00 r -> G>0 (110)^(2q+1) 0 1 r, and G0 is undefined: **halt** | 24q+9 | 120/120 | `Z2raw`, `Z2` (q>=1) |

Literal checks (`check_rules.py`): p up to 119 and q up to 39, each with the empty context and two random contexts r;
the run goes with no acceleration to the next left-edge A0 configuration (or the halt), the exact tape is compared,
and the cells of r must never be visited. Result: 0 failures. The step counts are exactly linear in p and q.

Derived rules:
- **digit**: E, then O applied 2p−1 times (the 0-run shrinks by one per O): S(n, k+1, j) -> S(4n+2, k, j) in
  D(n) = 8n² − 11n + 9 steps (n = 2p). So K digits take n0 to N = ((3n0+2)·4^K − 2)/3.
- **resets** on S(n, 0, j), by n mod 6:
  - n ≡ 4: S(4, (n−1)/3, j+1) in 4n+6 steps;
  - n ≡ 0: S(14, (n−6)/3, j+1) in 4n+47 steps (Z0, then O twice);
  - n ≡ 2: halt after 4n+1 steps, with 2(n+1)/3 + 1 + j ones on the tape.

Mechanism: a rightward sweep in the 6-step cycle A0 B1 E1 F1 G1 H0 (it moves a 0 two cells per cycle and reads one
cell ahead), then a turn at the right end, then a leftward sweep. For the digit rule the leftward sweep is C (O) or D
(E, which clears the 1s). For the resets it is the cycle G1 H1 F1, which rewrites every 3 cells as 110. The state that
reaches the blank left end depends on n mod 3 of the remaining cells: F0 continues (n ≡ 4), H0 continues (n ≡ 0),
and G0 halts (n ≡ 2).

## Recurrence and trajectory

From the blank tape the machine reaches S(10,0,0) at step 40. Writing N for the counter when the digits run out:

| reset | from | N (counter at reset) | N mod 6 | result |
| --- | --- | --- | --- | --- |
| 0 | S(10,0,0), step 40 | 10 | 4 | S(4,3,1), step 86 |
| 1 | S(4,3,1) | 298 | 4 | S(4,99,2), step 46,783 |
| 2 | S(4,99,2) | N2 = (14·4^99 − 2)/3 ≈ 1.87·10^60 | 4 | S(4,K3,3) |
| 3 | S(4,K3,3) | N3 = (14·4^K3 − 2)/3 | 0 | S(14,K4,4) |
| 4 | S(14,K4,4) | N4 = (44·4^K4 − 2)/3 | 2 | **halt** |

K3 = (N2 − 1)/3 = 624920350545162884932985258132674345425301164248863880394979, and K4 = (N3 − 6)/3.

The residues only need modular arithmetic, because f(n) = 4n+2 acts on residues:
- N2 mod 54 = 40, so K3 ≡ 4 (mod 9) (indeed K3 mod 27 = 22).
- The block count p = n/2 follows p -> 4p+1, which has period 9 mod 9. So N3/2 ≡ 3 (mod 9), N3 ≡ 6 (mod 18), and
  K4 ≡ 0 (mod 3).
- p -> 4p+1 is p -> p+1 mod 3, so N4/2 ≡ 7 ≡ 1 (mod 3) and N4 ≡ 2 (mod 6): the fifth reset halts.

Two independent scripts give this (`traj_mod.py`, which tracks K 3-adically, and `traj_exact.py`, which uses
`pow(4, K3, m)` with the exact K3). The Coq proof does the same with `Fm` (the iteration computed mod m), so the huge
numbers are never built.

**Literal check** (`trajectory.js`, 4·10^9 steps, no acceleration): it finds every S-configuration and checks that
each is the predicted successor of the previous one, reached after exactly the predicted number of steps. It found
13 configurations with 0 mismatches, from S(10,0,0) at step 40 through reset 1 (S(4,99,2) at step 46,783) up to
S(76458,92,2) at step 3,117,322,854 (`trajectory_main.txt`).

## Score

- Ones at the halt: sigma = 2(N4+1)/3 + 5 = (88·4^K4 + 47)/9.
- log10 K4 = 3.762395408·10^59, so sigma ≈ 10^10^(3.7624·10^59) = 10↑10↑10↑59.5755 (`sizes.py`, `sizes.out`).
- 2↑↑6 = 10^10^19727.78 < sigma < 2↑↑7 = 10^10^10^19727.78.
- Steps up to the halting configuration (G reading 0), exactly (add 1 if the halting transition counts):

  T = 40 + 46 + 45,499 + 1,198 + Dsum(4,99; N2) + (4N2+6) + Dsum(4,K3; N3) + (4N3+47) + Dsum(14,K4; N4) + (4N4+1),

  where Dsum(n0,K; N) = (8/15)[(N+2/3)² − (n0+2/3)²] − (65/9)(N − n0) + (179/9)K is the exact cost of K digit rules
  (checked against direct summation and against the literal anchor at step 46,783). So T = (8/15)N4² + O(N4).
- A1 variants: the same sigma, and T + 10 steps (A1 is read 5 times, once per reset, and each detour costs 2 steps).

Record comparison: 2↑¹¹2↑¹¹3 is far larger than 2↑↑7, so this machine is irrelevant to the BB(8) record. I did not
search external lists for the machine.

**Why the pipeline saw 8.52 digits per loop.** Quick_Sim uses 6-cell blocks, and its "Iterated Rule 7"
(`qs_prover2000.txt`) is `111111^v ... 101101^u -> 111111^(4096v + 42770) ... 101101^(u−3)`. That fuses six digit
rules (×4 each) into ×4096, so the cap is 10·log10(4096) ≈ 36 digits per loop, not 6. At 40 CPU-s the pipeline was
inside the phase after reset 2, about 7·10^4 digits into the ~6.2·10^59 digits of that phase.

## Formal proof

`bb8_list/proofs/BB8_76450_1RB1LG.v`, generated by `gen_halt.py main` from `halt_header.v.in` and `halt_tail.v.in`:
- `sweepB2`, `sweepB6`: hand-written rightward sweeps (by induction, 6 or 18 literal steps per block). The generic
  crossing derivation cannot produce them, because the cycle reads one cell ahead.
- Four generated crossing lemmas (C and D over 11, G and H over 111111).
- The phase lemmas `O1`, `Erule`, `Z4raw`, `Z0raw`, `Z2raw`. `planner8.py` (copied unchanged from the
  1RB0LG0RC1RG investigation) writes their scripts, with a matcher for the B sweeps.
- `Oiter`, `digit`, `digits` (induction on the digit count; `Fp k p` is the block count after k digits),
  and `Z4`, `Z0`, `Z2` on `Cf p k r` = S(2p, k, ·).
- Arithmetic:
  - `Fp_mod` (Fp k p mod m = Fm k p m);
  - `Fp_per9` and `Fp_per3` (periods 9 and 3);
  - `Fm 99 2 27 = 20`, by computation.
- `halt`: init (40 steps), then Z4, digits, Z4, digits, Z4, digits, Z0, digits, Z2; then `halted_halts` and
  `halts_multistep`.

The variant files come from `gen_halt.py a1LE` and `gen_halt.py a1RH`. Z2 is stated for n = 6q+8, which excludes
n = 2 and so covers `1LE` too.
