## Rules (ds nearest-first)

| rule | statement |
| --- | --- |
| R1 (a >= 1) | K(ds; a+1; b) -> K(ds; a; b+1) |
| R2 (nearest digit y+1 > 0, a = 0) | K(y+1 :: t; 0; b) -> K(y :: t; 2b+3; 0) |

| R4 (all-zero list of length n, a = 0) | K(0^n; 0; b) -> **K(1^n ++ 0^(2b+2); 1; 0)** |

Notes. (a) Valid for ALL b (including 0) and all k, n (including 0): no "b > k" condition, no halting cell (hence NOBOUNDARY).
(b) The rebuild is NOT the autoproof/DigitListOnes shape (rebuild with no zero digit): R4 leaves `2b+2` zero digits at the FAR end and `n` ones near the
counter. That is harmless: the totality argument needs no invariant, so `DigitListOnes.v` is not used. (c) After R2 the a R1-steps give b' = 2b+3 per digit step.

Non-halting on paper: every K(ds;a;b) has a successor K: a>0 -> R1; a=0, ds = 0^n -> R4; a=0, ds = 0^k ++ (y+1)::t -> R2 (k=0) or R3 (k>0).

## The remaining gap (precise): machine-level R3 and R4

Both cost quadratically in the list length (R4 steps: 187+72b for n=0, per-b increment 72+32n, quadratic in n; R3: 250+88b for k=0, per-b increment 88+32k),

  to the far end as `1111` and crosses `(11)^n`; `engine.explore(M, G)` reports OK, but `coqgen.loop_lemma` cannot frame the round ("framed round does not return to the loop shape"; the round contains an inner loop)
  -> **PASS** `G(j+2, i, T) -->+ G(j+1, i+1, T)` for any tail `T = 0 1 w`, any i: cost 32j+6; **the engine finds it (two sequential loops F>, C>) and both loop lemmas generate** (`explore9.py`, `dbg_loop2.py 2`);
  literal check j=2..8, i=0..4, m=8..20 (`conv1.py`)
  -> n+1 passes: `G(n+2,0,T) -->* G(1,n+1,T)`, and `G(1, n+1, 0 1^(4b+8))` **is** `K(1^n ++ 0^(2b+2); 1; 0)` as a tape (two applications of `align_lpow`).
- R3 = **R3a** `start -> M3(k,b) = (0101)^b <E (11)^k 1^5 (01)^4 11 (01)^y 11 t` (explorer OK)
