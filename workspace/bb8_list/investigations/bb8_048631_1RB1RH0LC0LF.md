## Configuration family

The head is in state E on the blank cell just right of the word. The right side is blank.

```
Z(k,n) = 0^inf (1110)^k 11 (10)^n E> 0^inf
```

- k is the number of unread (1110) digits and n is the counter.
- In Coq, `Zl k n l` is the same word with an arbitrary left part l in place of 0^inf.

The checks are in `check_rules.py` (`check_rules.out`, `check_rules.json`):
- b and j run over 0..59. T and R use three random 12-cell left contexts each.
- Each run goes with no acceleration to the first new rightmost cell reached in state E, or to the halt. The whole
  tape is compared, and the context cells must never be visited.
- Result: 0 failures. The step counts are exactly linear.

Derived rules, also checked literally:
- **digit** (n>=1): Z(k+1, n) -> Z(k, 9n+13) in D(n) = 120n² + 400n + 344 steps.
  - The path is R, then T n−1 times, which gives (1110)^(k+1) 1 (10)^(3n+1). Then T eats the "10" of the last
    (1110) digit, R fires on "111", and T runs 3n+3 more times.
  - 132 literal cases: contexts '', '1', '0110', '1010011'; k = 0..2; n = 1..11. Every step count equals D(n).
  - Coq: `digit` (as Zl (S k) (S n) l -->* Zl k (9n+22) l) and `digits`.
- **reset**: Z(0, n) -> 0^inf (10)^m E> with m = 3n+4, via R, T n−1 times and then L1. This takes
  12n² + 46n + 47 steps (39 literal cases; Coq `Z0`).
  - If m is odd, RO gives Z((m+1)/2, 2).
  - If m is even, RE halts.

Mechanism:
- The head sweeps left from the right end in the cycle F0/G1 over the (10)s, unchanged.
- At the separator it turns one "10" pair into three new pairs at the right end. So every (10) left of a separator
  becomes three (10)s right of it (T), and each (1110) digit costs two such rounds: n -> 3n+4 -> 9n+13.
- With the digits gone, the left end is blank. One pass (F moving right, 1010 -> 1110) then rewrites the (10)^m run
  into (1110) digits (RO).
- When m is even, the machine reaches A reading 1 next to another 1: A1 = 1RH, then H reads 1, which is undefined
  (RE).

## Recurrence and trajectory

- F(k, n) = f^k(n) with f(n) = 9n+13. After a reset to Z(k, 2), the counter at the next reset is
  N = F(k, 2) = (29·9^k − 13)/8.
- f flips parity, so N is odd exactly when k is odd.
- An odd k gives m = 3N+4 odd and the next counter k' = (3N+5)/2 = (87·9^k + 1)/16. An even k gives m even: halt.

| reset | from | k (digits) | result |
| --- | --- | --- | --- |
| – | blank tape | – | Z(1,2) at step 31 |
| 0 | Z(1,2) | 1 | Z(0,31) at step 1,655; m = 97; Z(49,2) at step 15,165 |
| 1 | Z(49,2) | 49 | N1 = F(49,2) ≈ 2.08·10^47 (odd), Z(k2, 2) |
| 2 | Z(k2,2) | k2 ≈ 3.11·10^47 | Z(k3, 2), k3 odd |
| 3 | Z(k3,2) | k3 | Z(k4, 2), k4 odd |
| 4 | Z(k4,2) | k4 | Z(k5, 2), **k5 even** |
| 5 | Z(k5,2) | k5 | N5 even, m5 = 3N5+4 even: **halt** |

The residues only need 2-adic arithmetic:
- f^(2^e) is the identity mod 2^e, because 9 has order 2^e mod 2^(e+3). So F(k,2) mod 2^e depends only on
  k mod 2^e.
- The chain is: N1 ≡ 15 (mod 32), so k2 ≡ 9 (mod 16). Then N2 ≡ F(9,2) ≡ 7 (mod 16), so k3 ≡ 5 (mod 8).
  Then N3 ≡ F(5,2) ≡ 3 (mod 8), so k4 ≡ 3 (mod 4). Then N4 ≡ F(3,2) ≡ 1 (mod 4), so k5 ≡ 0 (mod 2).
  Finally N5 ≡ F(0,2) ≡ 0 (mod 2).
- `traj_exact.py` (`traj_exact.out`) confirms this with k2 exact and 64-bit 2-adic precision below it:
  k3 ≡ 101, k4 ≡ 71, k5 ≡ 194 (mod 256).
- The rule "k ≡ 3 (mod 4) makes the next k even" holds because 87·9^k + 1 ≡ 16 (mod 32) for k ≡ 1 (mod 4) and
  ≡ 0 (mod 32) for k ≡ 3 (mod 4).
