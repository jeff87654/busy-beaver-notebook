3.1 Why `m8sweep` Missed F89 and Its 3 Siblings (`check_m8_nofit.py`)
In `bb8_m8sweep/xcands.json`, F89 (`i=266`) and its 3 siblings (`i=212, 276, 329`) are
listed with `tmpl = "L,D,P=1,u=01,s=011,d=2d+0,b=2b+1,S=00"`, `free = []`, `guards = []`.
Why? Because `dlscan` treated `011` as a separator AFTER each digit (`(01)^d 011`). In
F89's actual coding, `1` is a separator BEFORE each odd digit:
  K-config:  [D]0 0 0 [1 (01)^{d_1}] [1 (01)^{d_2}] ... [1 (01)^{d_n}]
When all digits $d_i = 2k_i + 1$ are odd, adjacent digits `[1 (01)^{2k_1+1}] [1 (01)^{2k_2+1}]`
have `0 1 1` at the boundary between them, which fooled `dlscan` into thinking `011` is a
post-digit separator and the last digit is unterminated! Consequently, when the list
shrinks to a single digit `[x]` (`[D]0 0 0 1 (01)^x`), there is NO `011` anywhere on the
tape, so `m8sweep`'s template follower failed to recognize `[x]` as an exhaustion moment
and reported `free = []`, `guards = []`.
