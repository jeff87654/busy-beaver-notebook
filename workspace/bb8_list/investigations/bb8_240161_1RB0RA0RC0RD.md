## Rules (all proved in Coq for all parameters; literal checks below)

| rule | statement (mirror notation, b = number of units) |
| --- | --- |
| R1 (a >= 1, any b >= 0) | K(ds; a; b) -> K(ds; a-1; b+2) |
| R2 (k = 0, b >= 1) | K(.., x+1; 0; b) -> K(.., x; b+2; 0) |
| R3 (1 <= k < b) | K(.., y+1, 0^k; 0; b) -> K(.., y, b+2-k, 1^(k-1); 1; 0) |
| halt (k = b) | the machine halts (C1) |
| R4 (digits all zero, b >= 1) | K(; 0; b) -> K(2, 1^(b-1); 1; 0) |
| R2 with b = 0 | halts (never reached: b >= 2 at every reset) |
| k > b | not characterized (never reached) |

Machine-level phases (planner8.py, exact symbolic execution; Coq lemmas in the proof file):
- `R1P`: E> 0 1 1 (01)^b 0 0 1 l -> E> 0 1 1 (01)^(b+2) 0 l (16 literal steps + 4b crossing steps): one right sweep
  D over the b-run and one left sweep G/H back, no dependence on the rest of the tape.
- `TR`: E> 0 1 1 (01)^b 0 0 0 rr -> (1) H> 0 1 (01)^b 0 0 rr (14 steps + 4b).
- `LOOP`: (1 l) H> 0 1 (01)^(r+1) 0 0 0 rr -> (1 0 0 1 l) H> 0 1 (01)^r 0 0 rr (11 steps + 4r). Each round moves one zero
  of the gap into a new `001` block on the left and costs one (01) of b. `LOOPS` iterates it k times.
- `FINAL`: ((100)^j 1) H> 0 1 (01)^(r+1) 0 0 1 (01)^y rr -> E> 0 1 1 (001)^j 0 (01)^(r+3) 0 (01)^y rr. With j = 0 this
  is R2, with j = k it is R3 (refill r+3 = b-k+2).
- If b runs out first (r+1 = 0 units) with a nonzero digit above, the machine reaches C1: planner confirms the halt
  `(100)^j 1 H> 0 1 0 0 1 (01)^y -> ... C> 1 ...`. This is the k = b case.
- `END4` (blank gap, all digits zero): ((100)^b 1) H> 0 1 0^inf -> E> 0 1 1 (001)^b 0 0 1 0 1 0^inf, i.e. R4.

## Why it never halts (the invariant)

The Coq lemmas (same shape as `BB8_76450_1RB1RA.v`; values of b are exact here):
- `R1iter`: K(ds; a; b) -->* K(ds; 0; B) with b + 2a <= B.
- `CH`: for b >= 1, K(x::U; 0; b) -->* K(0::U; 0; B) with b + x <= B (R2, then a = b+2 units of R1 give b -> 2b+4, x times).
- `EX`: K(1^j ++ (w+1)::U; 1; 0) -->* K(0^(j+1) ++ U; 0; B) with B >= w + j + 2.
- `IN`: if k = j+1 < B then K(0^(j+1) ++ v::U'; 0; B) -->* K(0^(j+2) ++ U'; 0; B2) with B2 >= B + v. R3 applies because
  k < B, it refills (B-k+2, 1^(k-1)), `EX` clears the refill with b >= B+3, and the induction on v continues.
- `CLR`/`GEN`: a configuration with all digits nonzero reaches the all-zero family Zc, and every reset on the way has k < b.
  A rebuild (R4) gives (2, 1^(b-1)), which is all nonzero again, so `Top B -->+ Top B'` for every B. The cycle never
  meets k = b (halt), and after a rebuild b is huge while the list has b-1 digits: the bound b >= k+1 is relative, not absolute,
  so the long list does not matter.
- `init_reach`: 67 literal steps from the blank tape give K(2; 1; 0); then `GEN`.
