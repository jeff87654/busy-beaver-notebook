# BB(8) holdout, subtask 48631: `1RB1RH_0LC0LF_0RH1LD_0RE1LF_1RA1RD_0LG0LE_1LB1LF_1RF---`

Source: holdout of BB(8) subtask 48631 (mxdys enumerator @ a41db6c); the undefined (halting) transition is H1.
The pipeline measured 10,101 / 21,323 / 35,789 digits at 2 / 10 / 40 CPU-s (1,379 / 1,967 / 2,725 loops), and the
run was still going at the time limit.

This machine differs in one transition from the proven halter `1RB1RH_0LC0LF_1LE1LD_0RE1LF_1RA1RD_0LG0LE_1LB1LF_1RF---`
(`bb8_048631_1RB1RH0LC0LF.md`, `proofs/BB8_48631_1RB1RH.v`): **C0 = 0RH instead of 1LE**.

## Verdict

**The machine halts**, at its 3rd reset (the parent halts at its 6th), with

- sigma = (261·9^k2 + 115)/16 ones, where k2 = 2,889,711.
- sigma ≈ 1.944·10^2,757,486 (2,757,487 decimal digits), that is sigma ≈ 10^10^6.4405.
  So 10↑↑2 < sigma < 10↑↑3 and 2↑↑5 < sigma < 2↑↑6.
- steps ≈ 13.5·N2² ≈ (2/3)·sigma² ≈ 10^5,514,972.4, where N2 = (29·9^k2 − 13)/8.

This is far below the BB(8) record bar 2↑¹¹2↑¹¹3, so the machine is **not a record candidate**. It is also far below
its parent (sigma ≈ 10↑10↑10↑10↑10↑47.47, between 2↑↑8 and 2↑↑9): changing C0 shortens the run from six resets to three.

**Confidence: proved (Coq PASS).** `bb8_list/proofs/BB8_48631_1RB1RH_C0_0RH.v` proves `Theorem halt : halts tm c0.`

## What C0 = 0RH changes

- In the parent, C0 fires only at the blank left end during a reset, as G0 (1LB) -> B0 (0LC) -> C0. In the first
  2·10^6 steps it fires twice: once from the blank tape and once at the first reset.
- Parent: C0 = 1LE writes a 1 and then E0 = 1RA writes another, so the rebuilt word starts with "11".
  - Then A reads that 1, A1 = 1RH, and H0 = 1RF continues.
- Here: C0 = 0RH writes 0 and goes straight to H reading 0 (H0 = 1RF). From that point the run is the parent's run
  with those two leftmost 1s missing.
- As a result, the left end of every configuration is "10" instead of one more (1110) digit, and the reset uses one
  extra T rule. The digit rules T, R, L1 and `digit` are the parent's, unchanged; they never use C0.

## Configuration family

The head is in state E on the blank cell just right of the word. The right side is blank.

```
Y(k,n) = 0^inf 10 (1110)^k 11 (10)^n E> 0^inf
```

- k is the number of unread (1110) digits and n is the counter.
- In the parent's notation, Y(k,n) = Zl k n l with l = 0^inf 10 (`0 >> 1 >> const 0` in Coq).

## Recurrence and trajectory

- F(k, n) = f^k(n) with f(n) = 9n+13. After a reset to Y(k, 2), the counter at the next reset is
  N = F(k, 2) = (29·9^k − 13)/8.
- f flips parity, so N ≡ k (mod 2).
- m = 3N+7 is odd exactly when N is even, that is when k is even. In that case the next digit count is
  k' = (3N+6)/2 = (87·9^k + 9)/16.
- If k is odd, m is even and the machine halts.
- Parent, for comparison: m = 3N+4, the machine continues on odd k, and k' = (87·9^k + 1)/16.

  (2/3)·sigma² ≈ 10^5,514,972.4.
- Record comparison: 2↑¹¹2↑¹¹3 is incomparably larger. sigma is also below 2↑↑6 and 10↑↑3, and far below the
  parent's 2↑↑8–2↑↑9.
- This is a trivial variant of the parent: one transition that is used only at the left end, the same digit
  mechanism, and a different reset offset (m = 3N+7 instead of 3N+4) that flips which parity continues.
- **Pipeline numbers.** Between the budgets the incremental rate is 19.08 digits per loop, which is
  10 × 2 × log10 9, exactly as for the parent. So Quick_Sim is inside the final k2 phase. It would need about 1.4·10^5
  more loops to reach the halt.
