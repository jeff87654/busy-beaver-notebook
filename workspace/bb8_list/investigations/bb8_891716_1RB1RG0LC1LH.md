## Structure

Cells: S = `11`, A = `10` on the tape. The screen family K(ds; a; b) = `1 (10)^d1 11 ... (10)^dn 11 (10)^a 11 (10)^b 11`, head in C on the blank
to the right, is the tape word `marker 1` + A^d1 S ... A^dn S A^a S A^b S. There is a second, **shifted family without the marker**
(the screen template does not parse it): `Ke(ds; a; b)` = the same word without the leading `1` (even length). I call the screen family `Ko`.
Both families obey the same three rules, and the rebuild of an exhausted `Ko` list passes through `Ke` and back.

(ds are listed far-first, the digit nearest the head last; in the Coq file they are nearest-first.)

| rule | statement | literal cost |
| --- | --- | --- |
| R1 | K(ds; a+1; b) -> K(ds; a; b+2) | 22b + 32 |
| R2 (k = 0) | K(.., y+1; 0; b) -> K(.., y; b+2; 0) | 26b + 40 |
| R3 (k >= 1 trailing zero digits) | K(.., y+1, 0^k; 0; b) -> K(.., y, b+2, 0^(k-1); 0; 0) | (4k+26)b + 8k + 40 |
| R4 (list all zero, n digits, a = 0, b >= 2) | Ko(0^n; 0; b) -> **Conv** Ke(0^b, 1, 0^(n-1); 0; 0) (n = 0: Ke(0^b; 1; 0)) | (4n+24)b + 4n + 19 |
| | Ke is then run with R1/R2/R3 until its list is all zero: Ke(0^m; 0; B2), m = b + n, and **B2 >= 2** (B2 depends only on n) | |
| | **Fin**: Ke(0^m; 0; B2) -> Ko(B2+2, 0^(m-2); 0; 0) (m >= 2); m = 1: Ko(; B2+2; 0) | (4m+22)B2 + 8m + 32 |

R2/R3 are one rule: stream form `S A^b S^(k+2) A^(y+1) rest -> S^(k+2) A^(b+2) S A^y rest` (rest arbitrary, even blank), k >= 0.
The new digit of a rebuild is c_n = B2_n + 2 with B2_0 = 2, B2_1 = 4, B2_2 = 12 (c = 4, 6, 14); B2_n is the b at exhaustion of Ke(1, 0^(n-1); 0; 0), a tower-rate
function. So the rebuild is the **same digit-list dynamics run on a list (0^b, 1, 0^(n-1))**, not a separate mechanism: the marker (left end) plays the role
of the new digit, and the doubling of b per decrement gives the tower growth. R4 on n >= 3 cannot be run literally (n = 3, b = 0 needs more than 2e10 steps),
which is why the 200k-step probes of the screen show T for n >= 3.

Trajectory from the blank tape (all literal): first K event `Ko(0; 0; 0)` at step 52 (exhausted, n = 1, b = 0: not a halting cell, Conv gives Ke(1; 0; 0) at step 75),
then Ke events 115, 147, 223 (`Ke(0; 0; 4)`, B2 = 4), `Ko(; 6; 0)` at step 367, drains to `Ko(; 0; 12)` at 1219 (R4 with n = 0, b = 12),
`Ke(0^12; 1; 0)` at 1526, `Ke(0^12; 0; 2)` at 1558 (B2 = 2), `Ko(4, 0^10; 0; 0)` at 1826, then (3, 2, 0^9), (3, 1, 2, 0^8), ... as in the lead notes.

## Why it never halts (proved)

Invariant `Inv(ds, a, b)` := a > 0, or ds has a nonzero digit, or b >= 2. Every Ko state satisfying it has a successor satisfying it:
- a > 0: R1 (b grows).
- a = 0 and a nonzero digit: R2 gives a = b+2 > 0; R3 gives a nonzero digit b+2.
- a = 0 and the list all zero: then b >= 2 by Inv, so R4 applies. The Coq proof does **not** compute the new digit: it shows Conv, then
  the exhaustion of Ke (lemma `EXH`: well-founded induction on the lexicographic order of the equal-length list rev ds ++ [a]; the B2 it produces is >= 2),
  then Fin. The result has the nonzero digit B2+2.

The halting transition is reached only from `Ko([]; 0; 0)` (empty list, a = 0, b = 0) via Ke([]; 0; 2) -> Fin with m = 0, which `Inv` excludes (the list length is invariant under
R1-R3 and R4 produces length b+n >= 2). The proof starts at `Ko([]; 6; 0)`, reached from the blank tape in 367 literal steps (skipping the exhausted state `Ko(0; 0; 0)` at step 52 whose b = 0 violates b >= 2).

## Machine-level lemmas (stream notation, all parameters, generated)

Planner `planner8.py` (m7 version, mode-2 crossings; crossing lemmas `cx_AL_01_01_c0`, `cx_CR_01_10_c1110`, `cr_CR_11_11`, `cr_FL_11_11`, `cr_HL_11_11`) derived
ENT (entry, b symbolic), LOOP (one iteration, loop counter symbolic) and EXT (last step) phases; each nested pass is ENT, then induction on the loop count with LOOP, then EXT
(the iteration crosses the S-run twice via the generated crossing lemmas, so the cost is bilinear):
- `R1v`: S A^b S A^(a+1) l -->+ S A^(b+2) S A^a l (single pass, no loop).
- `R23v`: S A^b S^(k+2) A^(y+1) l -->+ S^(k+2) A^(b+2) S A^y l (ENT/LOOP/`LOOPN_R23v`).
- `Conv_b2`: Ko(0^n; 0; e+2) -->+ S^(n+2) A S^(e+2) (the loop runs e times, then one step).
- `Fin_b2`: Ke(0^m; 0; e+2) -->+ S^(m+1) A^(e+4) marker (same shape). Only b >= 2 is needed because of `Inv`.

Pitfalls met: `rewrite align_lpow x [x] _ _` picks the wrong run when the left and right streams both carry a run of the same block, so `scr2coq.py` now
passes the count variable (`align_lpow x xs _ n`); bare numerals in lemma arguments are read in the symbol scope in this setup, so write `0%nat`;
`Forall_app` is an iff in Coq 8.20 and `ltac:(...)` arguments are elaborated before their types are known.

## Notes for the lead

- The same trick should transfer to the champion-rule rebuilders (champ12 and rebuilder_nbrs): an exhausted list is rebuilt by converting to the opposite alignment, running the
  ordinary rules, and finishing with a pass; the proof only needs the existence of the new digit (>= 1) and a bound b >= 2 at exhaustion, not its value.
  The new ingredients are (1) the nested ENT/LOOP/EXT glue for bilinear passes and (2) the lexicographic well-foundedness lemma on equal-length lists.
- The nob_screen.py grid (n = 0..6, b = 0..8) is not enough on its own for such machines: R4 at n >= 3 is out of reach of a literal probe, so its letters only cover n <= 2.
  The structural statement above (halting list state = Ko([]; 0; 0) only) is what decides it.
- The dlscan2 template does not parse the shifted family `Ke`; its rebuild letters come from the first Ko event after the whole Conv / Ke / Fin sequence.
