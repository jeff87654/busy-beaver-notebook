# BB(8) holdout, subtask 76450: `1RB0LF_1RC0RE_1LD1LC_1LA0LD_1LB1RA_1RG1LG_0LH0RD_---1RF`

Source: holdout of BB(8) subtask 76450 (mxdys enumerator @ a41db6c). The undefined transition is H0. Pipeline growth
at 2 / 10 / 40 CPU-s was 11,030 / 27,178 / 48,671 digits at 3,947 / 4,394 / 4,989 loops (2.79 -> 6.19 -> 9.76
digits per loop), still running at the time limit. The mxdys NG/RWL/CPS pre-filter could not decide it.

## Verdict

**The machine halts**, at its fourth reset (reset 3), with

- sigma = (32·4^K3 + 43)/9 ones on the tape, where K3 = (N2 − 4)/3, N2 = (26·4^55 − 2)/3, so
  K3 = 3749992175608486620605358459992290 (34 digits). Add 1 if the undefined H0 transition is counted as writing a 1.
- sigma ≈ 10^(2.2577·10^33) = 10↑10↑33.354 = 10↑10↑10↑1.523, so 2↑↑5 < sigma < 2↑↑6 (and 10↑↑3 < sigma < 10↑↑4).
- steps ≈ (4/5)·N3² ≈ (36/5)·sigma² ≈ 10^(4.5154·10^33) (exact formula below).

This is far below the BB(8) record bar 2↑¹¹2↑¹¹3, so it is **not a record candidate**.

**Confidence: proved (Coq PASS).** `bb8_list/proofs/BB8_76450_1RB0LF.v` proves `Theorem halt : halts tm c0.`
(busycoq, Individual82, Coq 8.20.1, compiles in about 23 s, no axioms). `python check.py BB8_76450_1RB0LF.v` printed:

```
PASS BB8_76450_1RB0LF.v: 1RB0LF_1RC0RE_1LD1LC_1LA0LD_1LB1RA_1RG1LG_0LH0RD_---1RF HALTS (machine-checked, no axioms)
```

Negative test: a copy with H0 changed to `Some (1, R, A)` compiles up to the final `halted_halts` step and fails
there (`coq_scratch/NegH0.v`). The sigma value is not part of the Coq theorem, but the theorem's halting
configuration has exactly 2w+7 ones with N3 = 6w+6, which is the sigma above. Every rule is also checked by exact
literal simulation, and the start of the trajectory by a 6·10^9-step literal run.

**Relation to the known machines.** It has the same kind of counter as the proven halter
`1RB1LG_1RC0RE_1LD1LC_1LA0LD_1LB1RF_1RC1LG_---0LH_1RA1LF` (`bb8_076450_1RB1LG1RC0RE.md`): n -> 4n+2 per digit, reset
decided by n mod 6. But the digit is `001` instead of `011`, the reset targets differ, and the halting class is
n ≡ 0 (not 2) mod 6. It is a relative, not a trivial variant: rows A and E–H differ, and every transition except H0 is used. It halts one reset
earlier than that machine, so its sigma is one exponential level smaller.

## Configuration family

Head in state A on the blank cell just left of the word, blank tape on both sides:

```
S(n,k,j) = 0^inf A>0 1^n (001)^k 0 0 0 1^j 0^inf        (n even)
```

- n is the counter, k the number of unread (001) digits, j the number of resets so far (it is only carried).

## Rules

All rules hold for an arbitrary right context r that is never visited, and for all parameter values shown.

| rule | statement | steps | literal check | Coq |
| --- | --- | --- | --- | --- |
| O (p>=0) | A>0 1^(2p+1) 0 r -> A>0 1^(2p+5) r | 12p+9 | 360/360 | `O1` |
| E (p>=1) | A>0 1^(2p) 001 r -> A>0 1 0^(2p-1) 1^5 r | 12p | 357/357 | `Erule` |
| R4 (q>=0) | A>0 1^(6q+4) 000 r -> A>0 1 (001)^(2q+1) 0001 r | 40q+25 | 120/120 | `R4raw`, `R4` |
| R2 (q>=1) | A>0 1^(6q+2) 000 r -> A>0 1^8 (001)^(2q-1) 0001 r | 40q+28 | 117/117 | `R2raw`, `R2` |
| R0 (q>=1) | A>0 1^(6q) 000 r -> H>0 0101 (001)^(2q-1) 0001 r, and H0 is undefined: **halt** | 40q−2 | 117/117 | `R0raw`, `R0` |

Literal checks (`check_rules.py`): p up to 119 and q up to 39, each with the empty context and two random contexts r.
The run goes with no acceleration to the next left-edge A0 configuration (or the halt). The exact tape is compared,
and the cells of r must never be visited. Result: 0 failures (`check_rules_main.txt`). The step counts are exactly
linear in p and q (`sizes.py` checks every value).

Derived rules:
- **digit**: E, then O applied 2p−1 times (the 0-run shrinks by one per O): S(n, k+1, j) -> S(4n+2, k, j) in
  D(n) = 12n² − 21n + 15 steps (n = 2p). So K digits take n0 to N = ((3n0+2)·4^K − 2)/3.
- **resets** on S(n, 0, j), by n mod 6:
  - n ≡ 4: R4, then O twice: S(10, (n−4)/3, j+1) in (20n−5)/3 + 42 steps;
  - n ≡ 2 (n >= 8): R2: S(8, (n−5)/3, j+1) in (20n+44)/3 steps;
  - n ≡ 0: R0: halt after (20n−6)/3 steps, with n/3 + j + 2 ones on the tape.
  - n = 2 behaves differently, but it never occurs.

Mechanism:
- **Rightward sweep:** the 10-step cycle A0 B1 E1 A1 F1 G0 H1 F0 G1 D0 moves a 0 two cells right and reads one cell
  ahead.
- **Turn at the right end:**
  - at `0` (odd n): the leftward sweep is C, which keeps the 1s. This is rule O.
  - at `001`: the leftward sweep is D, which clears them. This is rule E.
  - at `000`: the leftward sweep is the 5-step cycle D0 A1 F1 G1 D1, which rewrites every 3 cells as 001.
- **Which reset:** the phase of that cycle at the blank left end depends on n mod 3. D0 there gives R4, F0 gives R2
  (via a short bounce), and G0 then H0 halts (R0).

## Recurrence and trajectory

From the blank tape the machine reaches S(10,0,0) at step 48. Writing N for the counter when the digits run out:

| reset | from | N (counter at reset) | N mod 6 | result |
| --- | --- | --- | --- | --- |
| 0 | S(10,0,0), step 48 | 10 | 4 | S(10,2,1), step 155 |
| 1 | S(10,2,1) | 170 | 2 | S(8,55,2), step 22,609 |
| 2 | S(8,55,2) | N2 = (26·4^55 − 2)/3 ≈ 1.125·10^34 | 4 | S(10,K3,3), K3 = (N2 − 4)/3 |
| 3 | S(10,K3,3) | N3 = (32·4^K3 − 2)/3 | 0 | **halt** (j = 3) |

The residues only need modular arithmetic: with n = 2p the digit map is p -> 4p+1, which is p -> p+1 mod 3.
- N2/2 = Fp(55, 4) ≡ 8 (mod 9), since p -> 4p+1 has period 9 mod 9 and Fp(1, 4) = 17. So N2 ≡ 4 (mod 6) and
  K3 = 2·(N2/2 − 2)/3 ≡ 1 (mod 3).
- N3/2 ≡ 5 + K3 ≡ 0 (mod 3), so N3 ≡ 0 (mod 6): the fourth reset halts.

`traj_mod.py` follows this 3-adically, and `sizes.py` uses the exact K3 with `pow(4, K3, m)`. The Coq proof does
the same with `Fm` (the iteration computed mod m, `Fm 55 4 9 = 8`) and `Fp_per3`, so the huge numbers are never built.

**Literal check** (`trajectory.js`, 6·10^9 steps, no acceleration): it finds every S-configuration and checks that
each is the predicted successor of the previous one, reached after exactly the predicted number of steps. It found
11 configurations with 0 mismatches, from S(10,0,0) at step 48 through resets 0 and 1 (S(8,55,2) at step 22,609)
up to S(35498,49,2) at step 1,007,709,313 (`trajectory_main.txt`). The next one, S(141994,48,2), is due about
1.5·10^10 steps later, beyond the run. The run took about 4 CPU-minutes at Idle priority.

**Why the pipeline saw 9.76 digits per loop.**
- Quick_Sim (`qs_prover2000.txt`, `--recursive --max-loops=2000 --verbose-prover`, 0.3 s) proves
  "Iterated Rule 7": `111111^x ... 100100^y -> 111111^(4096x + 31850) ... 100100^(y−3)`.
- That rule fuses six digit rules (×4 each) into ×4096, so the cap is 10·log10(4096) ≈ 36 digits per loop.
- At loop 2000 it is two digits before the end of phase 2, with about 7.0·10^32 ones.
- At 40 CPU-s the pipeline was inside phase 3, about 8·10^4 digit rules into its K3 ≈ 3.75·10^33.

## Formal proof

`bb8_list/proofs/BB8_76450_1RB0LF.v` is generated by `gen_halt.py` from `halt_header.v.in` and `halt_tail.v.in`.
It is adapted from the 1RB1LG generator, and `planner8.py` is copied unchanged.
- **Hand-written lemmas:**
  - `sweepA2`, `sweepA6`: the rightward A sweeps (10 or 30 literal steps per block). The generic crossing derivation
    cannot produce them, because the cycle reads one cell ahead.
  - `crG6`: the leftward G sweep over `111111` blocks, where each block rewrites the first cell of the block
    before it. Its statement is `[1;1;1;1;1;1]^^n *> l <{{G}} 1 >> r -->* l <{{G}} 1 >> [0;1;0;0;1;0]^^n *> r`.
- **Generated lemmas:**
  - four crossing lemmas (C, D over 11; A, F over 111111);
  - the phase lemmas `O1`, `Erule`, `R4raw`, `R2raw`, `R0raw`, whose scripts are written by the planner.
- **Rules on `Cf p k r` = S(2p, k, ·):** `Oiter`, `digit`, `digits` (induction on the digit count; `Fp k p` is the
  block count after k digits), and `R4`, `R2`, `R0`.
- **Arithmetic:** `Fp_mod` (Fp k p mod m = Fm k p m), `Fp_per3` (period 3), and `Fm 55 4 9 = 8`, by computation.
- **`halt`:** init (48 steps), then R4, 2 digits, R2, 55 digits, R4, K3 digits, R0. Then `halted_halts` and
  `halts_multistep`.
