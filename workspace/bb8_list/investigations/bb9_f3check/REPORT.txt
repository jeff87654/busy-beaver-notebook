1. TOOLS (all mine, written from scratch here; y1-fable's pkf7/pkf8 were not used for any result below)
---------------------------------------------------------------------------------------------------------
wsim.cpp/.exe  Literal byte-tape simulator.  It has one jump, the record's clearing rule R0.3 applied ONLY in its exact
               form  Kt(ctx, X, 1^k; 1; r; t) -> Kt(ctx, 1^(k+1); 1; 3R+2; t)  (m = 1, d_1..d_k = 1, X = 1 mod 3, X >= 4).
               A multi-digit suffix is cleared one digit at a time, each with its own R.  pkf clears the whole suffix with
               one R; that differs only in the R values.
               --R a,b,.. gives the R of each clear in order, --Rdef the rest.  --cnt is optional counter acceleration
               (R4.c): only after two literal rounds with the same (k, X), C falling by 3 and no H0-left-0 event, it sets
               C to 6 + C mod 3, and the last rounds run literally.  Counter rounds never enter H (H0one = H0zero = 0 in
               every literal round), so skipping rounds hides no f3/M8 difference.
               Logs: every read of 0 in state H whose LEFT cell is 0 ("H0L0", the only place f3 and M8 can differ), counts
               of the others, every D0f moment (--d0: L, P, y, s in the Coq D0f convention, L = sketch L + 1), the halting
               token D(d), and the ones count.  --kt starts from a constructed Kt configuration (tokens, gaps zN).
lit.cpp/.exe   Two machines in lockstep from the blank tape, no jumps.  Reports the first differing step and any H visit.
orbit.py       My model of the cascade map (g, consumption 3/11/4/6/6, key, rho = (P_key-35) mod 5).
sweep.py, summ.py, grids.sh, launch.py, towres.py (power-tower residues).

    H0=0LI, I1=1RF, F0=1RG end in the same tape and position as M8's H0=1RG, in state G and 2 steps later.  So f3 = M8 until the
    first H0 event with a 0 to the left.  H is entered only through E0.

    B, which never reads E0.

    either machine is the H0 at world step 8111: the far-left start of M8's first exhaustion, left cell 0.  f3 diverges there
    (I0 = 0RC) and nowhere earlier.  My M8 run reproduces y1-fable's M8 control (HALT H1, ones 9866, class key 31/rho 4).  My
    f3 run reproduces y1-fable's f3 (HALT H1, ones 18287).  The second divergence is the far-left start of the second
    top-level exhaustion.  After that, no H0 event with a 0 to the left occurs, in this run or in any run below.

5. THE THREE QUESTIONS
----------------------
(a) Early halt?  No, in every phase that was checked.  H1 is the only undefined slot and H is entered only from E0.  Clears
    never read E0 (the champion's rules; lockstep check 2.2).  The literal phases P1, P3 and P5 were followed over the grids
    above with no H1 read.  The cascade and endgame are M8's (section 4).  Remaining risk: P1, P3 and P5 are checked on
    grids, not proved.  They are uniform in every grid, including non-real residues (P1 for every B >= 1, P3 for every
    R'' >= 1).
(b) Class forcing by R2'?  It is not needed.  All nine classes halt (section 4) and the real class is never used.  R2' only
    sets the parked length (rho), and R'' only sets the orbit.  The one residue fact used is R'' = 1 mod 5, to choose the
    top-level step lemma.  It is a theorem about U_5 outputs.
(c) Same cascade?  Yes (section 4).  The bookkeeping correction is in section 0.

6. RECOMMENDED COQ ROUTE (reuse bb9_c04_coq + bb8_resid/coq_m8)
--------------------------------------------------------------
 1. Machine lemmas for f3's table.  Re-run the C04 generators (bb9_c04_coq/gen: gen_step.py, gen_grp.py, mexp) with f3's
    table for every group used from the cascade entry on: G_rules (R1-R3), G_sub2..5, G_stop, G_entry, G_end, CBtail,
    G_p14_*, G_p20_*, k31's K_rf/K_x/K_e1/K_e2.  Same statements (D0f, Kt, Hc); only the step counts change, because each
    M8 H0 step is 3 f3 steps.  If some H0 event read an abstract left cell, the symbolic executor would stop there; the
    sweep says this does not happen.  This is preferable to a simulation proof: a "guarded" f3-M8 simulation would need the
    left cell of every H0 event in the abstract C04 lemmas.
 2. New prefix lemmas (three parametric groups, each like C04's 51-stage R1):
      EXH1-I0 : Kt(1^11;1;3b+2;0) -->* Kt(0,1,6b-2,13,1^4;1;2;3)          for all b >= 1
      TOP     : Kt(0,1^7;1;3R+2;3) -->* Kt(0,0,7,1^(12R+10);1;2;3)        for all R >= 1     (no H at all)
      ATE-I0  : Kt(0,0,1^(12R+11);1;2+3S;3) -->+ D0f 4 (36R+38) 2 1 (6S) l0    for all R, S (l0 = the far-left side)
    plus the top-level sub-step for L = 3 mod 5 at s = 1 (M8's reach_top used residue 4).  C04's G_top is the template.
 3. Clears: the record's CL lemma (CDPx/CHx in Step.v) twice for P2 and once for P4.  R'' = iter (2b-1) (U 5) (iter 4 (U 4) 0)
    (check the iteration counts against the CL lemma's d+1 convention: X = 3d+4 gives d+1 iterations).
 4. Arithmetic: R'' mod 5 = 1 (Euler on the tower, as Resid.v does for Bx).  L_start = 36R''+37 is odd and = 1 mod 3.  Feed
    Cascade.cascade_from_start with reach := f3's D0f family and Pm := 12R2'+11 - L1'.
 5. Score: EndU's lower half with R2 Bx -> R2' and depth_ge_R2 -> K >= R2'.  Then N > f_w(f_w(12R''+12)).  R'' >= 2B (each U
    iterate increases), so N > f_w(f_w(12B+27)) > every M8 halting count (coq_m8 m8_fgh_bracket).  The upper bound is not
    needed for the record claim.
 Effort: comparable to C04's dev (the generated groups dominate, about a day of Idle CPU), plus the three new groups.
