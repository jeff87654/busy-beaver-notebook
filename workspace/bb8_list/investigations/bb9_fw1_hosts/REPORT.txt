=========================================================================================================================
ANSWER: NEGATIVE. No MOVING-with-consumption or CREATES host with an accumulator-length rebuild exists among the
1347 graded looper/rebuild rows (7, 8 and 9 states). The only constant-shift grower is one 8-state machine (H8), and
an exhaustive H8 + 1-state screen (24,934 machines) finds no late halt. Nothing appended to OPEN_CANDIDATES.

1. METHOD (tools in this folder, all Idle, <= 2 cores)
   hpc.cpp (current build hpcw2.exe): literal chain probe. Round = run until a stable K-configuration (same outer
     prefix O and digit count n at 6 consecutive parseable K-moments; free-prefix parse from the template's u/s/S),
     then MODE 1 reset: keep O and the leading (most significant) digit literally, a = 0, b = b1. The machine then
     runs that digit down itself and reaches a GENUINE exhaustion every round, so many rounds are visible
     (blank-tape runs show only 1-3 exhaustions). Per round: lo (leftmost 1), leftmost visited cell, n, O.
     Env: HPC_WMAX (width cap), HPC_KMAX (K-moments per round), HPC_SLOTS (slot counts per round).
   mkpool.py -> pool.tsv: 1347 distinct LOOPER/REBUILD/MULTI/MULTI? rows from dl3_hits, dl3_triage7,
     triage7_1RB1LA, parents (7-state, 698), bb8_sample + calib (8-state, 16), roots9, c7m12, n1f0, n1f0c (9-state, 633).
   probe.py -> base_all.jsonl; classify.py -> cls_all.tsv: chains from the blank tape, b1 = 3 and 4, 6 rounds.
     Classes (rounds >= 2): STATIC (lo fixed), SHIFT (lo moves by one constant for both b1), OUT (lo moves outward by
     an amount growing with b1, i.e. Theta(b)), OUTc, CREATES (outer prefix longer for larger b1 / growing over
     rounds), NONE (halt / timeout / < 3 rounds). growth = rebuilt digit count larger for b1 = 4 than for b1 = 3.
   planted.py -> planted.jsonl; plsum.py -> plsum.txt: blocks {1^8, 1^9, (10)^6, (110)^5, (100)^5, (1100)^4} planted
     beyond the separator at gaps 1-3, 6 rounds: is a block consumed per round? does contact halt?
   h8g.py -> h8g.tsv: H8 + one new state (section 4).

   * H8 + 2 states is a 10-state question, not run.

5. CONCLUSION / LESSONS
   * All 7/8-state f_omega rebuild-loopers in the graded pool rebuild OUTWARD by Theta(b) per round. No BB(13)-style
     static separator exists among them; the earlier STATIC label was a no-exhaustion artefact. With <= 2 new states
     nothing outside the list survives an exhaustion, so the "moving separator / created counter" route needs a host
     class we do not have (an engine that rebuilds toward the accumulator side and leaves its outer end fixed or
     consumes from it). The one constant-shift grower (H8) drifts outward (counts rounds up) and absorbs every marker;
     H8 + 1 state is exhaustively negative at screening level.
   * Classify hosts with forced exhaustions (hpc MODE 1), not with blank-tape geometry.
   * Caveats: MODE 1 deletes the list right of the leading digit, so a gadget whose counter lives inside the list or on
     the LSD side would be destroyed by the reset (the h8g screen is biased against such designs); 16 7/8-state rows
     unresolved (tlist.txt); classification uses b1 = 3, 4 only.
   * Side result: the 23 dl3_hits + 2 triage7_1RB1LA W1-LOOPER rows (not in the earlier pool) have sqrt(t) tape width
     (runw.py): polynomial, not record class.
