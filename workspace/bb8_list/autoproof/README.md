# autoproof: automatic busycoq proofs for digit-list machines

Generates complete, machine-checked non-halting proofs (busycoq / Coq 8.20.1, checked by `proofs/check.py`)
for digit-list counters, with no hand-written phases.

## Pieces
- `engine.py`: symbolic execution on tapes with runs (built on `planner8.py`). When the head meets a run it cannot
  cross, it looks for a loop: peel one block, run one round, and check that the configuration comes back with the
  run one shorter and one block pushed onto a stack. Otherwise it splits cases (count = 0 / count > 0). Every
  stage can be checked against exact simulation with `validate.py` (`guided.py` follows the branches that agree
  with concrete values).
- `coqgen.py`: turns the proof tree into Coq: one lemma per stage (planner script), one induction lemma per loop
  (`X(S j) -->* X(1)` with `g^^j` pushed, framed so the stack is a variable), and the rule lemma with `destruct`
  for every split (all but the last round of a loop by the lemma, the last round step by step).
- `proofs/DigitListOnes.v`: the invariant half, proved once for any machine: if a family `Kc ds a b` satisfies
  R1 (count-down, `b -> f1 b >= b+1`), R2 (`a = f2 r >= r+2`, `b = 0`), R3 (borrow refilling with ones,
  refill `>= r+2`, `a3 >= 1`, `b = 0`) and R4 (rebuild with no zero digit, `a4 >= 1`), and the blank tape reaches
  the family, the machine never halts.
- `gen_digitlist.py SPEC.json OUT.v`: the four machine-level rules (explored and proved automatically), the
  family wrappers (`family_ones.v.in`), the start-up lemma (found by literal simulation) and the theorem.
- `auto_spec.py MACHINE KEY OUT.v`: derives the spec from the digit-list scan's fit (`kfit.py --params` on the
  key from `neighbors/dl_hits.tsv`) and runs the generator. Supported now: orientation L, separator 0, rules in the
  DigitListOnes class; anything else is reported as out of class.

## Nested loops (2026-10-05)
A loop whose round contains loops of its own (e.g. every round carries a pattern across a run `(11)^n` by an
inner shift loop; the rule then costs quadratically) is now generated:
- `engine.try_loop` runs the inner loops of a round in full (`accelerate` record key `result` = start with v = 0
  and `g^v` inserted; `engine.run_nested` executes a round to a target through such loops).
- `coqgen.loop_lemma`: when the framed round does not return to the loop shape by plain steps, the round becomes
  its own lemma `<loop>_round : X'(j) -->* X(j) + g` (stage lemmas between the inner loops, each inner loop a
  `full_loop_lemma`: `forall j, X(j) -->* X(0) + g^^j`, by induction). `X'(j)` is the configuration with one
  peeled block, exactly the one the engine computed the round from; the outer induction uses it with
  `j := S j`. (Starting from two peeled blocks lets the planner cut blocks differently, and a crossing can then
  jump over the end of the round.)
- `explore(..., positive={'b'})` with `rule_lemma(..., positive=('b',))`: a variable known to be >= 1. Its
  `v = 0` branch is left out and closed by `lia` from the hypothesis `(Hpos_b : 0 < b)`. Use it when the outer
  loop must be taken at the start configuration: otherwise the first round is unrolled step by step, and the
  `v = 0` restart of the loop found after it begins past the point where the target lies.
- Validation: `proofs/BB8_884431_1RB1RC.v`, generated by
  `investigations/bb8_884431_1RB1RC1LC0RE/opus/gen884431.py` (`R4b_loop3`, `R3b_loop2` are nested loops).
  `AutoBB8_048631.v` and `AutoBB8_240161.v` regenerate byte-identically from their specs, and both still pass
  `check.py`.
- Still by hand: a loop whose round starts where the head is not stuck (for 884431, iterating the PASS lemma
  `G(j+2, i) -> G(j+1, i+1)`: `PASSit` in that generator's template), and the choice of waypoints between rules.

## Not covered yet
- Families at the right end of the tape (orientation R): needs a mirrored family template.
- Other rule classes: the `1RB1RA` family (resets with `a3 = b3 = b2 = 1`, multiplicative R1; the earlier
  `gen_kcoq*.py` templates cover it by hand), champion-style borrows that keep zero digits, halting proofs.
